## 模块一、架构现代化与 Tauri 深度适配

> 这 10 个方向是 Tauri 迁移后的「基础设施」。不直接面向用户，但决定了后续所有功能的质量上限。它们解决的是「启动器自身的健康度」问题。

### #1 命令层实现深度补全

**功能描述**：对已注册的 260+ 个 Rust 命令进行系统性审查，标记每个命令的实现完成度。将命令分为四个等级——L0（占位符，返回 mock 数据）、L1（基本可用，核心路径能跑通）、L2（完整实现，含错误处理和边界条件）、L3（经过优化且有测试覆盖）。在 CI 流水线中自动检查覆盖率，拒绝 L0/L1 命令合并到主分支。

**用户价值**：用户不会直接感知到这个方向，但它是所有功能的基石。当用户点击一个按钮后，背后可能调用的是 L0 stub 命令（如 `launch_multiple_instances` 直接返回「不支持批量模式」），这意味着用户看到的是一个「假按钮」。补全命令实现 = 消除所有「假功能」。当前约 60% 的命令是 L1 或以下级别，这意味着用户每使用两个功能就有一个可能出问题。

**体验影响**：命令补全前——部分操作无响应或报模糊错误；补全后——所有 UI 上的按钮和操作都有真实的背后逻辑支撑。

**覆盖范围**：涉及全部 15 个命令模块，260+ 个命令。优先处理高频命令（启动、实例管理、模组管理），其次处理低频辅助命令。

---

### #2 Tauri IPC 通信协议优化

**功能描述**：当前前端与 Rust 后端之间通过 JSON 序列化进行通信。在启动游戏时，后端每秒可能产生数百条日志事件，每条事件都会被序列化为完整的 JSON 字符串、跨 IPC 传输、前端再反序列化。当 1000 条/秒的日志事件涌入时，前端的主线程被 JSON 解析和 DOM 更新占满，用户看到的是卡死或延迟严重的启动日志界面。优化方案包括：改为批量传输（100ms 合并一批日志）、使用 Tauri Channel API（比事件系统更高效）、对于高频日志使用固定格式的二进制协议减少序列化开销、实现背压机制（前端忙不过来时后端暂停推送）。

**用户价值**：用户在启动游戏时会看到一个实时滚动的日志面板。如果日志卡顿、延迟严重，用户无法判断启动是否正常进行，会反复重启或焦虑等待。优化后日志流畅滚动，启动进度一目了然。

**体验影响**：优化前——启动时日志面板掉帧、滚动不跟手、新日志延迟出现；优化后——即便面对大量日志，面板始终保持 30FPS+ 的流畅滚动。

**覆盖范围**：`launch-log`、`download-progress`、`launch-phase-update`、`launch-log-diagnosed`、`repair-progress` 等所有高频事件通道。

---

### #3 Rust 侧计算密集型任务卸载

**功能描述**：识别所有当前在 TypeScript 前端执行的 CPU 密集型操作——包括存档 NBT 解析、世界地图渲染、大文件 SHA-256 哈希、模组 jar 包分析——将它们全部迁移到 Rust 后端的专用线程池中执行。Rust 侧完成计算后，将结果以压缩格式返回前端，前端只需要展示，不需要参与计算。

**用户价值**：当前用户打开一个 500MB 的存档的健康检查时，前端可能卡死 10-15 秒，整个启动器界面无响应。迁移后，操作在后台执行，用户可以继续浏览其他页面，操作完成后弹出通知。对于「世界地图生成」这类操作，等待时间从 60 秒+ 缩短到 10 秒以内，从「不可用」变成「实用」。

**体验影响**：迁移前——重型操作导致整个启动器界面冻结、用户以为程序崩溃；迁移后——所有操作都有进度指示器，界面始终响应，用户可以随时取消。

**覆盖范围**：NBT 解析（存档读写、健康检查、统计面板）、文件哈希（增量资源补全、完整性校验）、图像渲染（世界地图、种子预览、结构预览）、字节码分析（模组安全扫描）。

### #4 多窗口架构设计

**功能描述**：当前 Bonjour 是单窗口应用——所有功能都挤在一个窗口中。这意味着用户在查看启动日志时无法同时浏览模组市场；崩溃报告只能覆盖主页面；设置面板切换后丢失之前的位置。多窗口架构允许启动日志、崩溃报告、设置面板、AI 助手等次要功能独立弹出为浮动窗口。每个窗口有自己的位置和大小记忆，窗口之间通过 Tauri 事件系统共享状态。

**用户价值**：用户在等待游戏启动时可以打开模组市场浏览；游戏崩溃后，崩溃报告自动在独立窗口中弹出，不打断用户当前的操作；AI 助手可以固定在屏幕右侧，随时提问。多窗口让启动器从「单任务工具」升级为「工作空间」。

**体验影响**：单窗口——频繁切换页面、上下文丢失、等待时无事可做；多窗口——并行操作、信息独立呈现、效率提升。

**覆盖范围**：主窗口（版本画廊 + 首页）、启动日志浮窗、崩溃报告窗口、设置窗口、AI 助手侧边栏窗口、服务器监控面板窗口。

---

### #5 Rust 侧 SQLite 数据层迁移

**功能描述**：当前所有数据（实例、模组、设置、存档备份、启动记录等）以 JSON 文件形式存储。每次需要读取实例列表时，整个 `instances.json` 被全量加载、解析、遍历。当用户拥有 50 个以上的实例时，这个操作耗时 1-2 秒。引入 SQLite 作为主存储后，实例列表查询变为 `SELECT * FROM instances ORDER BY last_played DESC LIMIT 20`，耗时降为毫秒级。JSON 文件保留为导入导出的交换格式。

**用户价值**：重度用户（50+ 实例、500+ 模组）打开启动器时，实例列表瞬间加载完成，不再有 1-2 秒的白屏等待。模组搜索变为 SQL 索引查询而非遍历 JSON 数组，在数百个模组中搜索的结果在按键的同时出现。启动记录的统计查询（如「本月启动次数最多的版本」）从不可能变为即时。

**体验影响**：迁移前——大量数据时列表加载延迟、搜索有感知延迟、统计功能因性能原因未开放；迁移后——所有数据操作即时响应、统计功能变得可能。

**覆盖范围**：实例表、模组表、备份表、启动记录表、设置键值表、快照元数据表。JSON 文件保留为导入导出格式。

### #6 启动器自身的性能剖析系统

**功能描述**：在 Rust 侧集成性能追踪框架，记录每个命令的执行耗时、内存分配、并发情况。前端提供一个「启动器性能仪表盘」页面，展示 P50/P95/P99 命令延迟、内存使用趋势、慢命令排行榜。这些数据可以选择匿名上传到服务端，帮助团队发现性能退化。

**用户价值**：普通用户不需要关注这个功能。但它是我们「最快启动器」品牌主张的量化证据。在 About 页面展示「95% 的操作在 50ms 内完成」，比任何营销文案都有说服力。对于遇到性能问题的用户，这个面板可以帮他们定位是哪个操作慢。

**体验影响**：开发者——性能回归在 CI 中自动发现；用户——信任「最快启动器」的承诺有数据支撑。

**覆盖范围**：全部 ~260 个命令的延迟追踪、内存追踪、并发度追踪。匿名遥测需用户明确同意。

---

### #7 条件编译：全平台差异化能力

**功能描述**：利用 Rust 的 `#[cfg(target_os)]` 条件编译，为 Windows、macOS、Linux 分别提供最优实现。Windows 上通过注册表检测已安装的 Java 版本和游戏目录；macOS 上使用 Keychain 安全存储账号凭据；Linux 上遵循 freedesktop 规范创建桌面文件和图标。每个平台暴露相同的 trait 接口，编译时自动选择对应的实现。

**用户价值**：Windows 用户——启动器自动发现系统中已安装的 Java，无需手动指定路径；macOS 用户——账号凭据存储在系统 Keychain 中，不会以明文 JSON 文件形式存在；Linux 用户——启动器正确集成到桌面环境，出现在应用菜单中。

**体验影响**：不做平台差异化——各平台体验割裂，某些操作需要用户手动完成（如手动输入 Java 路径）；做了平台差异化——各平台操作流畅自然，符合该平台用户的预期行为。

**覆盖范围**：Java 检测（注册表/mdfind/which）、凭据存储（Keychain/Credential Manager/libsecret）、桌面集成（快捷方式/启动器条目）、文件对话框（原生风格）。

---

### #8 构建流水线优化

**功能描述**：当前 release 构建使用了体积最优的编译选项，代价是编译时间达到 5-10 分钟。通过引入编译缓存、区分 CI 构建（速度优先）和发布构建（体积优先）、增量编译等手段，将 CI 中的编译时间降至 3 分钟以内，让开发者每次提交后能快速获得反馈。

**用户价值**：用户不直接感知。但更快的 CI = 更快的 bug 修复 = 更频繁的更新 = 更好的软件质量。

**体验影响**：开发者——从提交 PR 到看到测试结果从 15 分钟降至 5 分钟，开发效率提升 3 倍。

**覆盖范围**：cargo-chef 依赖缓存、GitHub Actions cache、sccache 编译缓存、debug/release profile 分离、增量链接。

---

### #9 错误处理体系统一

**功能描述**：当前 Rust 命令绝大多数使用 `Result<T, String>` 作为返回类型，错误信息是裸字符串（如 `"Version 1.20.1 not found"`）。前端收到后只能原样展示，无法区分错误类型、无法给出修复建议、无法做多语言翻译。统一错误处理体系要求所有命令返回结构化的 `AppError` 类型，包含：错误码（如 `E_VERSION_NOT_FOUND`）、中文消息、英文消息、修复建议（如「检查版本名称是否正确，或刷新版本列表」）、错误分类（用户可修复/系统错误/网络错误）。

**用户价值**：用户看到的错误信息不再是技术术语堆砌，而是清晰的中文说明 + 可行的下一步操作建议。例如，不再是 `"Failed to download version JSON: connection timeout"`，而是「网络连接超时，无法获取版本 1.20.1 的信息。建议：1) 检查网络连接 2) 切换下载源 3) 稍后重试」。

**体验影响**：统一前——错误信息不可理解、用户不知道怎么修、只能来论坛求助；统一后——大部分错误用户可自行解决、减少社区支持负担。

**覆盖范围**：全部 15 个命令模块、260+ 个命令。需定义约 50-80 个错误码覆盖所有场景。

---

### #10 自动化端到端测试体系

**功能描述**：当前代码仓库中没有可见的测试代码，所有 260+ 个命令都没有自动化测试。建立三层测试体系：Rust 单元测试（每个命令函数的逻辑正确性）、Rust 集成测试（多个命令协作的场景，如「创建实例 → 安装模组 → 启动游戏」的完整流程）、Playwright 端到端测试（模拟真实用户从打开启动器到进入游戏的全路径操作）。全部在 CI 中自动运行。

**用户价值**：每当有新代码合并时，自动化测试会模拟「用户从安装到启动游戏」的完整流程。任何可能破坏这个流程的代码变更都在合并前被拦截。用户不会再遇到「更新后启动器不能用了」的情况。

**体验影响**：有测试——每次更新用户有信心升级；无测试——每次更新都是赌博。

**覆盖范围**：核心启动流程（安装 → 配置 → 启动 → 进游戏）、实例管理流程、模组安装流程、账号登录流程、更新流程。

## 模块二、首次体验与安装向导

> 这 8 个方向定义了用户与 Bonjour 的「第一次接触」。在所有竞品中，这是最被忽视的环节——PCL2/HMCL/PrismLauncher 都是用户下载后面对空白界面自行摸索。Tauri 的 5MB 安装包让「下载即用」从口号变成现实。

### #11 零配置启动向导

**功能描述**：用户下载启动器（仅 5MB）后，双击打开，进入一个三步向导。第一步：自动检测硬件配置（CPU、内存、显卡、磁盘空间），展示给用户确认。第二步：根据硬件配置推荐最适合的 Minecraft 版本（低配机器推荐 1.16.5 + Sodium，高配机器推荐最新版 + 光影），同时允许用户自行选择。第三步：自动下载匹配的 Java 运行时、下载推荐的游戏版本、创建第一个实例。全流程可视化展示进度，用户无需做任何技术决策。

**用户价值**：一个从未玩过 Minecraft 的用户，从下载 Bonjour 到进入游戏世界，只需要 4 分钟和 3 次点击。对比 PCL2 首次使用需要先下载 Java、手动配置路径、下载版本、理解加载器概念——整个过程 15-20 分钟且充满挫折。

**体验影响**：有向导——新手感觉「这启动器在帮我」，从焦虑变安心；无向导——新手面对空白界面无所适从，70% 在 5 分钟内关闭。

**覆盖范围**：硬件检测、版本推荐、Java 下载、首次版本安装、进度可视化。

---

### #12 迁移助手：从竞品无缝切换

**功能描述**：自动扫描用户电脑上已安装的其他启动器（PCL2、HMCL、PrismLauncher、MultiMC、官方启动器），读取它们的配置文件，列出所有可迁移的实例、存档、模组、服务器列表。用户勾选想要迁移的内容，一键导入到 Bonjour。迁移过程保留原有的配置结构，模组和存档不会丢失或损坏。

**用户价值**：切换启动器的最大阻力不是功能对比，而是「我几百个小时的存档和精心配置的模组都在旧启动器里」。迁移助手消除了这个阻力。一个 PCL2 的深度用户可以在 5 分钟内将所有数据迁移到 Bonjour，无需手动复制文件夹、无需担心配置丢失。

**体验影响**：有迁移助手——用户「抱着试一试」的心态下载 Bonjour，数据迁移后「回不去了」；无迁移助手——即使认同 Bonjour 的优势，也因为迁移成本而放弃。

**覆盖范围**：PCL2 配置（JSON 格式 + 版本目录结构）、HMCL 配置（hmcl.json）、PrismLauncher/MultiMC 配置（instance.cfg）、官方启动器数据。

---

### #13 智能 Java 运行时管理

**功能描述**：启动器内置 Java 版本管理器。自动检测系统中已安装的 Java（包括通过注册表扫描、PATH 环境变量、常见安装目录），展示每个 Java 的版本号和路径。当需要的 Java 版本未安装时，自动从 Adoptium API 下载最合适的构建。支持并行安装多个 Java 大版本（Java 8、17、21 等），每个游戏实例自动关联到兼容的 Java 版本。

**用户价值**：Minecraft 1.16.5 需要 Java 8，1.18+ 需要 Java 17，1.20.5+ 需要 Java 21。普通玩家不需要知道这些——启动器自动处理。不需要手动去 Oracle/Adoptium 官网下载安装包、不需要配置环境变量、不需要担心版本冲突。

**体验影响**：智能管理——Java 相关问题（版本不对、未安装、路径错误）从行业平均 25% 的启动失败原因降至 < 5%。

**覆盖范围**：系统级 Java 检测（注册表 / PATH / 常见目录）、Adoptium API 集成、并行多版本共存、自动版本匹配、下载进度展示。

---

### #14 预检系统：启动前自动诊断

**功能描述**：用户在「启动」按钮上点击之前，预检系统已经在后台运行。它检查所有可能导致启动失败的条件：Java 是否安装？版本是否兼容？分配的内存是否超出系统可用量？磁盘空间是否足够？显卡驱动是否过旧？操作系统版本是否支持当前 MC 版本？检查结果分为三个等级——通过（绿色）、警告（黄色，不影响启动但建议修复）、阻断（红色，必须修复才能启动）。每个问题旁边有「一键修复」按钮。

**用户价值**：用户在点击启动前就知道会不会出问题。不用反复点击启动→报错→修复→再启动→再报错。对于阻断级问题（如「磁盘空间不足 200MB」），启动按钮直接禁用并给出清理建议；对于警告级问题（如「显卡驱动版本较旧」），用户可以自主决定是否继续。

**体验影响**：有预检——启动失败率大幅降低，用户体验流畅；无预检——用户反复试错，产生挫败感。

**覆盖范围**：Java 检测、内存检测、磁盘空间、显卡驱动、操作系统兼容性、mod loader 兼容性、文件完整性。共 50+ 检查项。

---

### #15 后台静默更新

**功能描述**：利用 Tauri 的 updater 插件实现启动器自身的自动更新。当新版本发布时，启动器在后台静默下载增量更新包（约 2MB），下载完成后不立即安装，而是在下次启动器冷启动时自动替换。整个过程用户无感知，仅在成功后通过系统托盘通知「已更新到版本 X.X.X」。更新包经过数字签名验证，确保不被篡改。

**用户价值**：用户永远使用最新版本，获得最新的功能、bug 修复和安全补丁，但不需要手动下载安装包、不需要经历安装向导、甚至不知道更新发生了。对比 PCL2 需要手动去网站下载新版本安装包。

**体验影响**：静默更新——用户打开启动器就能用，版本永远最新；手动更新——大量用户运行着旧版本，遇到已被修复的 bug。

**覆盖范围**：版本检查、增量下载、签名验证、静默替换、更新通知、回滚机制。

---

### #16 视觉效果首次展示（WOW Moment）

**功能描述**：用户首次打开启动器时，看到一段 3 秒的品牌开场动画——Minecraft 风格的像素方块从四面汇聚形成 Bonjour Logo，然后无缝过渡到色彩浓郁的版本画廊主页。动画设计为多层级：支持 WebGL 的高配机器看到完整的粒子动画；中配机器看到简化版；低配机器看到静态渐变过渡。

**用户价值**：这是用户对 Bonjour 的第一印象。在竞品都是白色网格/空白侧边栏的市场中，一段精美的开场动画传递的信息是：「这个启动器不一样，它是精心设计的」。第一印象决定了用户是否愿意继续探索。

**体验影响**：有 WOW Moment——用户截图发到社交媒体（「这个启动器的动画太好看了」）；无 WOW Moment——用户打开后和竞品没有感知差异。

**覆盖范围**：Canvas/WebGL 粒子动画、framer-motion 过渡、多层级性能模式自动切换、可选跳过、后续启动也可开启。

### #17 区域自感知配置

**功能描述**：启动器首次启动时自动检测用户所在的地理区域（不获取精确位置，仅判断地区），然后对可用的下载源进行延迟测速，自动选择最快的源。中国用户自动使用 BMCLAPI 镜像；亚太用户优先 Modrinth CDN；欧美用户使用 Mojang 官方源。当首选源不可用时，自动切换到备用源。

**用户价值**：国内用户不需要手动配置 BMCLAPI 镜像地址就能获得满速下载；国际用户不需要面对 Mojang 官方源在国内 100KB/s 的龟速。一个澳大利亚留学生回国后，下载源自动从 Mojang 切换到 BMCLAPI，下载速度从 2MB/s 提升到 30MB/s。

**体验影响**：自动选择——全球 95% 用户首次下载速度 > 5MB/s；手动配置——大量用户不知道可以切换下载源，忍受极慢的下载速度。

**覆盖范围**：区域推断（测速而非 IP 定位）、多源延迟测试、自动选择、故障自动切换、手动覆写选项。

---

### #18 离线模式降级策略

**功能描述**：Rust 侧定时执行网络连通性检测（DNS 解析 + HTTP 请求），当检测到网络不可用时，启动器自动切换到离线模式。离线模式保留所有本地可用的功能：查看已安装版本、启动离线游戏、管理实例配置、浏览本地模组、查看本地存档。需要网络的功能（模组搜索、版本下载、云端同步）被标记为「离线不可用」，网络恢复后自动恢复。

**用户价值**：在没有网络的场景（火车上、学校宿舍断网、WiFi 故障），用户仍然可以启动已安装的 Minecraft 版本进行单机游戏。不会因为断网而导致启动器本身不可用。

**体验影响**：断网时——离线模式自动切换，核心功能完全可用；网络恢复时——自动恢复在线功能，无感切换。

**覆盖范围**：网络心跳检测、离线功能白名单、在线功能灰化标记、网络恢复自动切换、离线通知。

## 模块三、核心启动引擎

> 这 10 个方向是启动器存在的根本理由。如果启动游戏这个核心流程不可靠，其他所有功能都是空中楼阁。关键变化：部分核心引擎逻辑仍在前端 TypeScript 中，需要下沉到 Rust。

### #19 启动流程可视化仪表盘

**功能描述**：将 Minecraft 的启动过程分解为 7 个可视化阶段——验证阶段（账号、版本）、Java 初始化、依赖库下载、资源文件下载、游戏文件解压、类加载、窗口创建。每个阶段用一个彩色节点表示，当前阶段高亮，已完成阶段变为绿色。节点之间用连线表示流程，节点大小表示该阶段耗时。鼠标悬停在节点上时展示该阶段的详细日志。

**用户价值**：普通用户第一次看到「Minecraft 启动到底在干什么」。当启动卡在某个阶段时，用户可以一眼看出卡在哪里（比如「依赖库下载」阶段一直转圈）。不用翻看几百行的日志才能定位问题。

**体验影响**：可视化时间线——5 秒看懂启动进度和瓶颈；原始日志——需要技术背景才能理解，99% 的用户看不懂。

**覆盖范围**：7 阶段状态机、Canvas 时间线渲染、阶段耗时统计、节点交互悬停、异常阶段高亮。

---

### #20 启动日志智能诊断引擎

**功能描述**：将启动日志分析引擎从 TypeScript 前端迁移到 Rust 后端。引擎维护一个可热更新的诊断规则库（YAML 格式），包含数百条已知的 Minecraft 启动错误模式。当日志流经引擎时，规则被并行匹配，命中后用中文白话输出诊断结果和修复建议。例如，原始日志是 `"Caused by: java.lang.NoClassDefFoundError: net/minecraftforge/..."`，引擎输出：「检测到 Forge 安装不完整，缺少核心类文件。建议：1) 重新安装 Forge 2) 如果使用了整合包，请重新下载整合包。」

**用户价值**：Exit Code 1 这个错误码对 99% 的用户毫无意义。智能诊断引擎将「看不懂的技术错误」翻译为「听得懂的问题描述 + 做得到的修复步骤」。用户不再需要去贴吧/论坛发帖求助（平均等待 2 小时），而是立即获得修复指引。

**体验影响**：有诊断——启动失败后立即看到中文诊断和建议，85% 的失败可自行修复；无诊断——用户面对一堆英文日志不知所措，只能求助社区。

**覆盖范围**：100+ 条诊断规则（第一阶段）、正则预编译匹配、YAML 热更新规则库、中英文双语输出、修复建议分级。

---

### #21 JVM 参数调优向导

**功能描述**：提供三个层级的 JVM 参数配置方式。小白模式：一键自动推荐最优参数（基于系统内存和 CPU 核心数）。进阶模式：可视化滑块调节内存分配（最小/最大内存）、GC 选择（G1GC/ZGC/Shenandoah）、JIT 编译器阈值等，每个滑块旁边有中文解释。专家模式：自由文本编辑 JVM 参数，但有语法高亮和实时校验。

**用户价值**：大多数玩家不知道「-Xmx4G -XX:+UseG1GC」是什么意思。自动推荐模式给出的配置效果不低于专家手动调优的 90%。进阶玩家可以通过滑块直观理解每个参数的效果，不需要去 StackOverflow 查文档。

**体验影响**：自动推荐——一键获得最优性能；可视化滑块——理解参数含义的同时完成配置；自由编辑——专家不觉得受限。

**覆盖范围**：自动推荐引擎（基于 sysinfo）、可视化滑块（内存/GC/JIT）、专家模式编辑器（语法高亮+校验）、预设方案库。

---

### #22 崩溃报告自动收集与分析

**功能描述**：游戏崩溃时，Rust 侧自动收集多维度的系统快照——游戏崩溃堆栈、系统进程列表、内存分布、显卡驱动信息、磁盘状态、当前实例的模组列表和版本。这些信息被组装为结构化的崩溃报告，用户可以一键匿名上传到社区知识库。知识库使用向量搜索匹配历史上相似的崩溃案例，返回已知的解决方案。用户的隐私数据（账号、存档内容）不会被上传。

**用户价值**：遇到崩溃不用手动去 crash-reports 文件夹找日志、不用在论坛上手动描述自己装了什么模组——启动器已经帮用户整理好了全部诊断信息。上传后几秒内就能匹配到解决方案，而不是在论坛上等回复。

**体验影响**：自动收集——崩溃后一键上报、秒级匹配方案；手动收集——用户不一定能找到 crash-reports 文件夹、论坛发帖描述不完整、等 2 小时+ 才有回复。

**覆盖范围**：崩溃堆栈解析、系统快照采集、结构化报告组装、脱敏上传、向量搜索匹配、方案推荐。

---

### #23 增量资源补全

**功能描述**：在安装 Minecraft 版本时，不会盲目下载全部文件。首先解析版本 JSON 清单，计算出需要的全部文件列表；然后扫描本地已有的文件（通过 SHA-1 哈希校验确认完整性）；最后只下载缺失或损坏的文件。下载过程支持断点续传，中断后从上次的位置继续。

**用户价值**：版本重装或修复时，如果已经有 80% 的文件，只需要下载剩余 20%。对于网络较差的用户，这节省了 80% 的下载等待时间。下载中断后不需要从头开始，而是从中断点继续。

**体验影响**：增量下载——版本修复只需几秒到几十秒；全量重新下载——每次修复都要等 5-10 分钟。

**覆盖范围**：版本清单解析、本地文件哈希校验、差异列表生成、并发下载（8 线程）、断点续传、下载进度展示。

---

### #24 启动耗时基准测试

**功能描述**：每次启动游戏时自动记录各阶段耗时，建立用户个人的启动耗时基准线。当某次启动显著偏离基准时（如比平均慢 30%），自动标注并尝试归因（如「本次启动比平均慢 12 秒，检测到新增模组 create-1.20.1.jar 可能是原因」）。提供可视化的启动耗时趋势图。

**用户价值**：用户装了一个新模组后，发现启动变慢了，但不知道是哪个模组导致的。基准测试自动告诉用户：「你上次启动花了 45 秒，这次花了 68 秒，慢了 23 秒。新增的模组 X 体积较大（45MB），建议关注。」用户不再需要手动排除法来找出慢模组。

**体验影响**：有基准——启动变慢时立即知道原因，可在 10 秒内定位；无基准——靠感觉和经验排查，可能花 20 分钟。

**覆盖范围**：7 阶段计时、个人基准线建立、异常检测（偏离 30%+）、归因分析、趋势图表。

---

### #25 多版本并行启动

**功能描述**：支持同时运行多个 Minecraft 实例。每个实例使用独立的数据目录（通过硬链接共享只读的 libraries 和 assets），各自独立的 Java 进程，互不干扰。启动器统一监控所有运行中实例的状态，可以在任意窗口查看各自的日志和控制台。

**用户价值**：测试模组兼容性时，用户想同时运行有模组和无模组的两个客户端对比 FPS；玩整合包服务器时，想同时开客户端和本地测试服务器。这些场景以前需要开两个不同的启动器甚至两台电脑。

**体验影响**：可多开——一个启动器管理多个游戏窗口，进程状态集中监控；不可多开——场景受限，需要切换实例重启。

**覆盖范围**：独立数据目录隔离、硬链接共享只读资源、多进程监控、进程状态面板、统一退出管理。

---

### #26 快速启动面板

**功能描述**：在系统托盘的右键菜单中动态展示最近玩过的版本列表（最近 5 个），每个版本显示名称和上次启动时间。点击任意版本直接在后台启动游戏，无需打开主窗口。支持设置一个「默认版本」，双击托盘图标直接启动。

**用户价值**：用户想快速进入游戏时，不需要打开启动器窗口、找到版本、点击启动——只需要右键托盘图标，选择版本，游戏就启动了。从「想玩」到「玩到」从 4-5 次操作减少到 1-2 次。

**体验影响**：快速启动——1 次操作进入游戏；传统方式——打开窗口→浏览列表→选择版本→点击启动。

**覆盖范围**：托盘菜单动态更新、最近版本列表、默认版本设置、双击托盘启动、游戏启动后托盘状态更新。

---

### #27 游戏进程守护

**功能描述**：Rust 侧直接管理 Minecraft 游戏进程的句柄，通过操作系统信号机制（Unix SIGCHLD / Windows Job Object）监听进程退出事件。当游戏异常退出时（崩溃、被杀进程、系统关机），在 0.1 秒内检测到，弹出恢复选项面板：重启游戏、查看崩溃日志、回退到上一个快照、一键修复（自动运行预检和修复）。

**用户价值**：游戏崩溃后，用户可能正在做别的事情甚至离开了电脑。进程守护立即弹出通知和恢复选项，而不是让用户几分钟后回来才发现游戏已经崩溃了。恢复选项让用户可以从崩溃中快速回到游戏。

**体验影响**：信号驱动——崩溃后 0.1 秒检测到，立即弹出恢复面板；轮询检测——崩溃后 5-10 秒才发现，用户已离开。

**覆盖范围**：进程退出信号监听、崩溃即时检测、恢复选项面板、自动诊断、快照回退。

---

### #28 热配置注入

**功能描述**：对 Minecraft 的配置文件进行分类——哪些修改需要重启游戏才能生效（如 JVM 参数、模组增删），哪些可以热加载（如资源包切换、光影切换、部分模组的客户端配置）。对于可热加载的配置，通过文件监控实时检测到变化，将新的配置注入到正在运行的游戏进程中。

**用户价值**：切换光影包、换资源包不再需要重启游戏——在启动器中切换后，游戏中实时生效。对于调试模组配置的玩家，不用反复重启游戏来测试配置效果。

**体验影响**：热加载——50% 的配置调整无需重启，调试效率提升 5 倍；全冷重启——每次配置调整都要退出→改配置→重启→进游戏。

**覆盖范围**：配置文件分类（热加载/需重启）、文件变化监控、热加载通道、配套轻量 Mod。

## 模块四、实例与版本生态系统

> 这 12 个方向解决的是「如何高效管理多个 Minecraft 版本/实例」的问题。重度用户可能同时维护生存档、创造测试档、服务器测试档、不同整合包——当前竞品的扁平列表管理方式在超过 10 个实例后效率急剧下降。

### #29 实例分组与标签

**功能描述**：支持用文件夹式层级结构组织实例——例如「生存档」文件夹下放所有生存相关的实例，「测试用」文件夹下放临时测试实例。同时支持自由标签系统——可以为实例打上「高配」「光影」「联机」「怀旧」等标签，标签可以多选和组合筛选。

**用户价值**：一个拥有 30 个实例的用户，通过分组和标签可以在 3 秒内定位到目标实例，而不是在扁平列表中翻页查找。标签系统还支持交叉筛选——比如筛选同时有「科技」和「1.20.1」标签的实例。

**体验影响**：树状结构 + 标签——管理 20+ 实例的效率提升 70%；扁平列表——超过 10 个实例后定位困难。

**覆盖范围**：树状文件夹、拖拽排序、自由标签创建、多标签筛选、标签颜色编码。

---

### #30 实例模板系统

**功能描述**：将任意实例保存为模板——模板包含 JVM 设置、模组列表（不含模组文件本身，只含引用）、资源包配置、服务器地址等。新建实例时从模板克隆，自动下载模板中引用的模组、应用相同的配置。模板可以导出为文件分享给社区。

**用户价值**：用户为某个整合包精心调优了一套配置，想基于它创建新的测试实例时，不需要从头配置。直接从模板克隆，30 秒内获得功能等价的新实例。社区可以分享「最佳 Forge 1.20.1」等模板，降低新手的配置门槛。

**体验影响**：模板克隆——新建实例的配置时间从 10 分钟降至 30 秒；无模板——每次新建都要重新配置所有项。

**覆盖范围**：模板创建（序列化配置 + 模组引用）、模板克隆、模板导入导出、模板市场。

---

### #31 版本兼容性评分卡

**功能描述**：为每个 Minecraft 版本维护一张五维评分卡——模组覆盖率（该版本有多少可用模组）、服务器适配（主流服务端是否支持）、稳定性（已知 Bug 密度）、开箱即用度（无需额外配置的程度）、性能基准（该版本在不同硬件上的表现）。每个维度用 0-10 的评分和颜色编码直观展示。

**用户价值**：新玩家面对 1.16.5 到 1.21 十几个版本不知道选哪个。评分卡一目了然——1.20.1 的模组覆盖率 9.2 分、稳定性 9.5 分，而 1.20.5 模组覆盖率仅 4.1 分（因为生态还没迁移过来）。用户 30 秒做出决策，而不是在网上搜索「哪个版本模组最多」。

**体验影响**：评分卡——决策时间从 3 分钟降至 30 秒；无评分卡——靠经验和搜索做决策。

**覆盖范围**：五维评分模型、数据定期爬取更新、可视化评分卡、版本推荐排序。

---

### #32 版本间差异对比

**功能描述**：选择两个 Minecraft 版本（如 1.20.1 和 1.20.4），展示这两个版本之间的差异摘要——新增了什么方块和生物、改了什么机制、地形生成有什么变化。信息来自 Minecraft Wiki 的结构化解析，用图文卡片的形式呈现，不是技术 Patch Note，而是玩家能看懂的变化。

**用户价值**：玩家想从 1.20.1 升级到 1.20.4，但想知道「升了有什么不同」。差异对比页面用一个 5 秒可扫读的卡片展示关键变化，而不是让用户去读几十页的英文 Wiki。

**体验影响**：图文摘要——5 秒看懂版本差异；原始 Wiki——需要 10 分钟阅读英文页面。

**覆盖范围**：版本差异数据（从 Wiki 结构化解析）、图文卡片展示、高亮重要变化。

### #33 时间机器：实例状态快照

**功能描述**：对实例的完整状态（模组列表+版本、JVM 配置、资源包列表、服务器配置）创建轻量快照。快照只存储与上一个快照的差异 + 元数据，单个快照 < 50MB。在时间线界面上可以浏览历史快照，支持一键回滚到任意历史状态。

**用户价值**：用户装了 5 个新模组后发现冲突导致崩溃，想回到装模组之前的状态。传统做法是手动记忆装了哪些模组、一个一个卸载、还要回想之前的配置。时间机器一键回滚到 10 分钟前的状态，10 秒内完成。

**体验影响**：一键回滚——10 秒恢复之前状态；手动恢复——20-30 分钟的排除和撤销操作。

**覆盖范围**：Copy-on-Write 快照存储、差异压缩、时间线可视化、原子性回滚、快照导出。

### #34 实例导入/导出（可移植实例包）

**功能描述**：将实例打包为 `.bonjour-pkg` 格式——包含版本信息、模组列表（URL 引用而非 jar 文件本身）、配置文件和资源包索引。好友收到 `.bonjour-pkg` 文件后导入到 Bonjour，启动器自动下载引用的模组并应用配置。文件体积小（通常 < 1MB），因为不包含模组 jar 文件本身。

**用户价值**：想和朋友玩完全一样的模组配置，不需要逐个截图模组列表让朋友手动下载。导出一个 < 1MB 的包发给朋友，朋友拖入启动器就自动配置好。

**体验影响**：一键导出导入——3 分钟完成全套配置迁移；手动配置——双方各自花 20 分钟对齐模组列表。

**覆盖范围**：bonjour-pkg 格式定义、zip 打包（Rust）、模组引用列表、导入自动下载、完整性校验。

### #35 实例存储分析

**功能描述**：递归扫描每个实例的目录，计算 breakdown——versions 占多少、libraries 占多少、assets 占多少、mods 占多少、saves 占多少、logs 占多少。用饼图和树状图可视化展示。标注可安全清理的冗余文件（如旧版本的 libraries 中不被任何实例引用的文件、超大日志文件）。

**用户价值**：用户的 `.minecraft` 目录大了几百 GB，不知道被谁占的。存储分析一眼看出——saves 占了 60%（一个大型存档 50GB+）、logs 占了 15%（几年前的日志没清理）、libraries 有 20GB 是旧版本残留。用户一键清理，平均可释放 20-30% 的空间。

**体验影响**：可视化 + 一键清理——3 分钟释放几十 GB 空间；手动排查——逐个文件夹点开看大小，几乎不可能完成。

**覆盖范围**：递归目录大小计算（Rust walkdir）、饼图/树状图渲染、安全清理规则、一键清理。

**体验影响**：全貌看板——用户了解自己的游戏习惯，回顾游戏历程；无看板——记忆碎片化，只知道最近做了什么。

### #37 过期版本智能降级指引

**用户价值**：用户安装了很多版本但只玩其中一两个，其他版本占着磁盘空间。智能降级提醒帮用户识别「僵尸版本」，给出迁移建议，让用户做出清理决策。

**体验影响**：智能引导——用户做出有信息支持的决策；无引导——大量无用版本堆积。

**覆盖范围**：版本健康度评估、阈值触发、迁移推荐、一键清理选项。

### #38 版本注解（社区评论）

**用户价值**：用户选择版本时可以看到真实玩家的评价，而不仅仅是评分卡的数字。例如「1.20.1 Forge 版在多人服务器上有随机掉线问题，建议用 Fabric」——这种信息评分卡无法传达。

**体验影响**：社区评价——用户获得评分卡之外的实战经验；仅评分卡——缺少真实用户的声音。

**覆盖范围**：轻量评论系统、评价投票、官方标注、评论筛选。

### #39 数据目录健康检查

**功能描述**：定期扫描 `.minecraft` 数据目录，检测三类问题——损坏文件（通过 Hash 校验发现）、孤儿文件（不被任何版本引用的残留 jar 包）、超大日志文件（超过 100MB 的日志）。生成健康报告，标注问题文件并提供一键修复（重新下载损坏文件、删除孤儿文件、压缩或删除超限日志）。

**用户价值**：用户玩了半年后，`.minecraft` 目录可能积累了各种残留问题——某个 mod jar 下载不完整导致启动失败、去年的日志文件占了 2GB、旧 Forge 版本的残留 library。健康检查一次性发现并修复这些问题，提升启动成功率。

**体验影响**：定期检查——95% 的文件级问题被自动发现和修复；无检查——问题积累到导致启动失败才发现。

**覆盖范围**：Hash 校验损坏检测、依赖图孤儿文件分析、日志文件大小检查、一键修复。

### #40 实例关联启动自动化

**功能描述**：配置实例之间的启动依赖关系——例如「启动客户端实例 A 之前，先启动服务器实例 B」、「当服务器实例 C 退出时，自动关闭客户端实例 D」。依赖关系可视化为连线图，启动顺序自动化执行。

**用户价值**：玩某个整合包需要同时开服务器和客户端，每次都手动先开服务器→等加载→再开客户端。关联启动让这一切自动完成——点击一次「启动环境」，服务器先启动，加载完成后客户端自动启动。操作从 5 步降到 1 步。

**体验影响**：自动化——一键完成复杂的多实例启动序列；手动——每次都要记住顺序和执行。

**覆盖范围**：启动依赖配置（DAG 图）、顺序启动队列、依赖状态监控、级联关闭。

## 模块五、模组管理革命

> 这 12 个方向将模组管理从「文件管理器 + 搜索客户端」升级为「模组体验构建器」。核心洞察：玩家不想要模组，玩家想要的是通过模组获得的游戏体验。

### #41 全局模组搜索引擎

**功能描述**：一个搜索框同时查询 CurseForge、Modrinth、GitHub Releases、MCBBS 镜像，实时聚合结果去重。搜索结果展示模组图标、名称、一句话描述、兼容版本、下载量、评分。搜索结果支持中文搜索（通过模组中文名称索引增强）、分类筛选、排序切换。

**用户价值**：用户搜索「小地图」，不需要去 CurseForge 搜一次、Modrinth 搜一次、去 MCBBS 搜一次——一个搜索框覆盖所有来源。中文搜索「小地图」能找到英文的 Xaero's Minimap，因为模组的中文名已经被索引。

**体验影响**：全局搜索——2 秒返回聚合结果，一次搜索覆盖所有平台；分散搜索——需要在 3-4 个网站间切换，重复搜索。

**覆盖范围**：CurseForge API、Modrinth API、GitHub Releases API、中文名称索引增强、结果去重合并。

### #42 模组批量安装队列

**功能描述**：从整合包页面、推荐列表或社区分享链接中，一键添加 10-20 个模组到安装队列。后台自动解析每个模组的依赖关系、检查模组间的已知冲突、并发下载所有模组文件。下载完成后统一安装到实例的 mods 目录，并生成安装报告。

**用户价值**：以前装 20 个模组需要逐个搜索→逐个下载→逐个确认→担心冲突→手动排查。现在一键添加，5 分钟后所有模组安装完成并附带冲突报告。

**体验影响**：批量安装——20 个模组 < 5 分钟；逐个手动——20 个模组 > 30 分钟。

**覆盖范围**：任务队列系统、依赖图并发解析、预装冲突检测、安装报告生成。

### #43 版本组合推荐（Modpack-less 体验）

**功能描述**：用户选择想要的体验方向（科技、魔法、冒险、建筑、休闲、空岛），系统基于「模组关联度模型」自动推荐一组 15-30 个模组。关联度模型基于社区大数据——「装了 AE2 的玩家，90% 也装了 JEI 和 The One Probe」。推荐结果可以预览每个模组的功能和评分，支持增删替换。

**用户价值**：很多玩家不喜欢整合包——太重、太多不想要的模组、启动慢。但他们也不知道「科技体验」需要装哪些模组。Modpack-less 推荐给出一组轻量模组，下载量只有整合包的 1/5，启动时间只有 1/3，但体验接近。

**体验影响**：智能推荐——获得接近整合包的体验，但更轻量、更自由；整合包——全有或全无，定制困难。

**覆盖范围**：体验分类矩阵、关联度模型、推荐引擎、预览界面、增删替换交互。

### #44 实时冲突检测沙箱

**功能描述**：在选定一组模组后，Rust 启动一个 headless Java 进程，该进程加载一个轻量 Java Agent，监控所有模组的类加载过程，检测冲突——ID 冲突（两个模组注册了相同的方块 ID）、类加载冲突（两个模组提供了同一个类的不同版本）、MixIn 冲突（两个模组对同一个类做了 MixIn 注入导致目标类不一致）。检测结果以结构化报告返回。

**用户价值**：用户在装模组之前就知道会不会冲突，而不是装了 50 个模组→启动→崩溃→逐个排查。冲突检测报告明确指出「模组 A 和模组 B 在类 net/minecraft/world/level/Level 上有 MixIn 冲突」。

**体验影响**：预检冲突——安装前知道能否正常运行；装后崩溃——装了才发现冲突，逐个排除耗时数小时。

**覆盖范围**：headless Java Agent、类加载器监控、ID 冲突检测、MixIn 冲突检测、冲突报告生成。

### #45 模组更新策略控制

**功能描述**：支持为每个模组设置独立的更新策略——仅安全更新（只更新修复 Bug 的补丁版本，如 1.0.1 → 1.0.2）、同大版本更新（如 1.x → 最新的 1.x）、最新版（总是更新到最新版本）。语义版本分析自动判断更新类型（Major/Minor/Patch）。用户可以批量设置同一策略。

**用户价值**：用户不想冒险更新可能导致兼容问题的 Major 版本更新（如 1.0 → 2.0，API 可能不兼容），但希望自动获得 Bug 修复（如 1.0 → 1.0.3）。分级策略让自动更新变得安全可控。

**体验影响**：分级更新——自动更新引入的兼容性问题 < 2%；无分级——要么不更新（留在旧版），要么全更新（可能引入问题）。

**覆盖范围**：语义版本分析、三级更新策略、独立模组策略、批量设置。

### #46 模组社区评价聚合

**功能描述**：聚合 CurseForge、Modrinth 的评分，叠加 Bonjour 社区的中文评价。每个模组卡片展示——综合评分（加权平均，越近的评价权重越高）、中文评价标签（「稳定」「吃配置」「必装」「有Bug」）、评价列表。

**用户价值**：中国玩家在 CurseForge 上看到的全是英文评价，且评价未必反映中文环境下的表现。中文评价和标签让玩家获得更贴近自己使用场景的信息。

**体验影响**：中文评价——降低信息门槛，用户更快做出决策；全英文评价——信息获取效率低。

**覆盖范围**：多平台评分聚合、时间衰减加权、中文评价系统、标签系统。

### #47 性能影响评级

**功能描述**：基于社区众包的性能测试数据，为每个模组标注性能影响等级——几乎无影响（启动和 FPS 均无明显变化）、略有影响（启动增加 < 5 秒或 FPS 降低 < 5%）、明显影响（启动增加 5-20 秒或 FPS 降低 5-20%）、严重影响（启动增加 > 20 秒或 FPS 降低 > 20%）。标注具体数值（如「启动增加 8 秒，FPS 降低 12%」）。

**用户价值**：用户看到「TerraForged」模组标注「严重影响：启动增加 25 秒」，可以选择不装或接受代价。不用装了之后才发现卡得不行然后再卸载。

**体验影响**：有评级——装模组前就知道性能代价，做出知情选择；无评级——装了之后性能下降，逐个排查元凶。

**覆盖范围**：众包性能测试数据采集、统计修正、四级评级、具体数值展示。

### #48 配置迁移工具

**功能描述**：当模组从旧版本升级到新版本时，配置文件格式可能发生变化。配置迁移工具检测新旧版本的配置 schema 差异，自动迁移仍然支持的旧配置项。对于不再支持的废弃配置项，标注并给出替代方案。

**用户价值**：用户更新了 10 个模组的大版本，不需要逐个打开配置文件夹对比新旧配置文件。迁移工具自动完成 80% 的配置迁移工作，剩余 20% 给出明确的处理建议。

**体验影响**：自动迁移——80% 的配置自动处理，20% 有明确指引；手动迁移——逐个打开文本文件对比，容易出错。

**覆盖范围**：配置 schema diff、自动翻译映射、废弃标记、Top 100 模组优先支持。

### #49 模组文件分析器

**功能描述**：选择一个 `.jar` 模组文件，分析器自动提取——模组名称、版本号、支持的 MC 版本、支持的模组加载器（Forge/Fabric/Quilt）、依赖列表、入口类、包含的 MixIn 配置。如果是从不明来源下载的模组，还会标注安全风险（如包含 `Runtime.exec` 调用）。

**用户价值**：用户从一个 QQ 群下载了一个 `.jar` 模组，不知道它到底是什么版本、支持什么加载器、有没有恶意行为。分析器 2 秒给出完整报告，用户在安装前做出安全判断。

**体验影响**：文件分析——不明模组的元数据和安全性一目了然；盲装——装了不兼容或有安全风险的模组导致各种问题。

**覆盖范围**：jar 内元数据解析（mods.toml / fabric.mod.json / mcmod.info）、字节码安全扫描、依赖列表提取。

### #50 模组分享链接

**功能描述**：为每个模组生成分享卡片——包含模组图标、名称、版本、一句话描述。分享形式有两种——链接（通过社交平台、QQ、微信分享）和二维码（手机上扫码直接打开安装页面）。接收方点击链接/扫码后，启动器自动打开并开始安装该模组。

**用户价值**：想给好友推荐「Xaero's Minimap」，不需要发 CurseForge 链接让他自己去搜。生成一个分享卡片，好友扫码后在 Bonjour 中一键安装。

**体验影响**：分享卡片——推荐→扫码→安装，转化率 > 30%；传统链接——推荐→打开网页→找到下载→手动安装，转化率 < 5%。

**覆盖范围**：分享卡片生成、短链接、二维码、扫码安装唤起。

### #51 多模组加载器实例共存

**功能描述**：同一个 MC 版本下可以创建不同模组加载器的实例——如「1.20.1 Forge」「1.20.1 Fabric」「1.20.1 NeoForge」。实例名称自动包含加载器标识，列表中通过图标和颜色区分不同的加载器。切换对比界面可以直观看到两个加载器实例的模组列表差异。

**用户价值**：用户在犹豫「Forge 还是 Fabric」，可以同时维护两个加载器的实例，而不是创建两个版本后搞混哪个是哪个。

**体验影响**：自动区分——多加载器管理不混乱；手动记忆——容易混淆，游戏打不开才发现选错了加载器。

**覆盖范围**：加载器后缀自动命名、图标颜色标识、切换对比界面。

---

### #52 模组元数据云端增强

**功能描述**：本地模组的 `.jar` 文件通过 SHA-256 计算指纹，上传到云端数据库匹配——返回完整的元数据（模组名称、版本号、描述、作者、兼容性、图标）。本地模组扫描后，原本显示为「unknown-mod-1.0.jar」的未知文件变为「Just Enough Items 12.0.2 — 查看物品合成配方」。

**用户价值**：用户的 mods 文件夹里可能有几十个文件名不规范的 jar 包（如 `mod_v2_fixed_final.jar`）。云端增强后，这些文件的真实身份被揭示，用户可以清理重复和过期版本。

**体验影响**：云端增强——「unknown」模组从 60% 降至 < 10%；纯本地扫描——大部分模组只看文件名无法识别。

**覆盖范围**：本地 SHA-256 指纹计算、云端指纹数据库（定期同步 CurseForge/Modrinth）、元数据返回匹配。

## 模块六、整合包系统

> 这 8 个方向围绕整合包的全生命周期——发现、安装、定制、更新、分享。整合包是 MC 社区最重要的内容形式之一，但当前启动器对整合包的支持远不完善。

### #53 跨平台整合包一键安装

**功能描述**：支持拖入 `.zip` 文件或粘贴整合包链接，自动识别格式（CurseForge / Modrinth / FTB / Technic / MultiMC），解析 manifest，下载所有引用的模组，安装到自动创建的实例中。安装过程展示进度条和模组列表。

**用户价值**：用户下载了一个 CurseForge 整合包 zip，不需要手动解压→复制 manifest→找到每个模组的下载链接→逐个安装。拖入 zip 文件，5-10 分钟等待后，整合包实例可以直接启动。

**体验影响**：一键安装——拖入即可，等待自动完成；手动安装——解压、找模组、逐个下载，很多新手做不了。

**覆盖范围**：5+ 主流格式解析器、manifest 依赖解析、并发下载、自动配置注入。

---

### #54 整合包创建工坊

**功能描述**：可视化整合包编辑器——左侧是已安装的模组列表，中间是画布（整合包的模组集合），右侧是模组详情。用户将模组拖入画布，自动解析该模组的依赖并提示添加。画布支持版本锁定（指定某个模组的固定版本）。完成后一键导出为标准格式（CurseForge / Modrinth）或自用实例。

**用户价值**：制作一个简单的整合包不需要手动写 manifest JSON、逐个记录模组版本。拖入 30 个模组 → 自动处理依赖 → 导出，全程 15 分钟。

**体验影响**：可视化编辑器——制作简单整合包 15 分钟；手动制作——写 manifest + 逐个下载 + 打包，2 小时+。

**覆盖范围**：模组拖入画布、自动依赖解析、版本锁定、多格式导出。

---

### #55 整合包增量更新

**功能描述**：记录用户已安装的整合包版本。当整合包更新时，引擎比较新旧版本的模组列表差异，只下载新增/更新/删除的模组，而不是重新下载整个包。更新过程为原子操作——如果更新中断，自动回滚到旧版本。

**用户价值**：一个 200MB 的整合包更新后，实际只改了 3 个模组（约 15MB）。增量更新只下载这 15MB，而不是重新下载 200MB。更新流量节省 70%+，下载时间从 5 分钟降至 30 秒。

**体验影响**：增量更新——更新流量小、速度快、中断可回滚；全量重新下载——每次都重下整个包。

**覆盖范围**：版本 diff 引擎、增量下载、原子更新、失败自动回滚。

---

### #56 整合包分身（Pack Fork）

**功能描述**：Fork（派生）现有整合包为个人分支——在保留原包更新能力的同时，添加或删除个人偏好的模组。当原包更新时，个人分支自动合并更新，冲突的模组通过可视化界面解决（保留原包的还是保留分支的）。

**用户价值**：用户喜欢「Enigmatica 9」整合包，但想加一个自己喜欢的小模组。Fork 后，用户加了模组，当 Enigmatica 9 更新时，用户的个人分支也会自动更新，不会因为手动改了而失去更新支持。

**体验影响**：Fork + 自动合并——个人定制 + 持续更新两不误；手动修改——改了之后不敢更新原包，怕覆盖修改。

**覆盖范围**：Git-like 分支模型、三路合并策略、冲突可视化解决、自动合并。

---

### #57 整合包评分与发现

**功能描述**：多维评分系统——完成度（任务/进度是否完整）、稳定性（崩溃率）、性能（最低配置要求）、难度（新手友好/硬核）、创新度（是否引入了独特的玩法）。基于协同过滤推荐「玩了 X 包的玩家也玩了 Y 包」。

**用户价值**：上千个整合包，用户不知道该玩哪个。评分系统帮助筛选——要找新手友好的休闲包？筛选「难度 ≤ 3」+「评分 ≥ 4.5」。协同过滤推荐让用户发现他们可能喜欢但从没听说过的包。

**体验影响**：多维筛选 + 推荐——平均 2 次搜索找到满意包；无筛选——平均 5 次下载尝试才找到满意的。

**覆盖范围**：五维评分模型、协同过滤矩阵、个性化推荐、评分展示。

### #58 整合包测试实验室

**功能描述**：在沙箱环境中测试整合包的兼容性——Rust 创建临时目录 → 下载整合包模组 → 启动 headless 游戏实例 → 检测启动日志 → 生成兼容性报告（启动是否成功、是否有模组冲突、加载时间预估）。

**用户价值**：用户下载了一个 200 模组的整合包，安装前想知道「我的电脑能跑得动吗」、「会不会启动就崩溃」。测试实验室 2 分钟后给出报告：「预计启动时间 45 秒、发现 2 个可能冲突（AE2 + RS 可能 ID 冲突）、最低内存需求 4GB。」

**体验影响**：安装前测试——知道能不能跑再决定装不装；装后崩溃——200 模组装了半小时，启动失败，浪费时间。

**覆盖范围**：沙箱目录创建、headless 启动测试、启动日志分析、兼容性报告。

### #59 整合包多人同步

**功能描述**：创建「整合包房间」——发起人选择整合包版本，生成房间码。参与人输入房间码，自动安装相同版本的整合包（含相同的模组列表和配置）。文件传输通过 P2P（局域网内）或中继服务器（异地）加速。

**用户价值**：四个人想一起玩同一个整合包，不需要每个人手动下载同一个 zip、各自安装、祈祷版本一致。发起人建房间，其他人输入码，5 分钟后所有人拥有完全一致的整合包环境。

**体验影响**：房间同步——4 人同步 < 10 分钟，版本 100% 一致；各自安装——每人 20-30 分钟，版本可能不一致导致联机失败。

**覆盖范围**：房间创建、P2P 文件传输、中继服务器、版本指纹校验。

### #60 整合包性能基准

**功能描述**：为整合包建立性能基准数据库——最小配置要求（CPU/内存/显卡）、推荐配置、在不同硬件上的实测 FPS 范围、实测启动时间。数据来自社区的匿名性能上报。

**用户价值**：整合包作者声称「轻量优化」，但装了 300 个模组。性能基准用数据说话——「该整合包在 GTX 1060 + 16GB RAM 上实测 FPS 30-45，启动时间 2 分 15 秒」。用户判断自己的电脑能不能跑，不需要装了才知道。

**体验影响**：性能基准——装前就知道性能表现；单纯描述——靠作者一句话判断，容易踩坑。

**覆盖范围**：社区性能上报、数据清洗、配置要求推断、可视化性能卡片。

## 模块七、存档与世界管理

> 这 10 个方向是 Tauri 迁移后性能优势最明显的模块。存档操作涉及大量 NBT 解析、文件 I/O、图像渲染——Rust 比 JS 快 10-100 倍，让很多原本「不可行」的功能变得实用。

### #61 存档健康检查与修复

**功能描述**：对存档进行全面体检——level.dat 完整性检查（NBT 解析校验）、区块数据损坏扫描、玩家数据异常检测（坐标越界、物品非法值）。问题分为三级——轻度（可自动修复，如 level.dat 缺少非关键字段）、中度（半自动修复，如区块数据部分损坏，用空白区块替换）、重度（需手动介入，如 level.dat 完全损坏）。

**用户价值**：用户打开存档时，Minecraft 原版只说「Failed to load world」，没有任何修复手段。存档健康检查不仅告诉用户「哪里坏了」，还帮用户自动修复轻度问题。80% 的常见存档问题可以自动修复。

**体验影响**：自动修复——大部分存档问题一键解决；原版——只告诉你坏了，不帮修。

**覆盖范围**：NBT 解析校验（Rust fastnbt）、区块数据扫描、三级问题分类、自动修复引擎。

---

### #62 存档时间线回放

**功能描述**：配合自动备份功能，将存档的每个备份版本展示在时间线上。点击任意时间点的备份，预览该时间点的世界地图缩略图、玩家位置、游戏天数等摘要信息。支持选择一个备份版本恢复。

**用户价值**：用户想知道「上周三我的基地是什么样的」，在时间线上点击上周三的备份，预览缩略图确认是想要的状态，一键恢复。不需要手动去 backups 文件夹按日期翻找。

**体验影响**：时间线可视化——最近 30 天的存档状态一目了然，选择恢复只需 3 次点击；手动翻备份文件夹——按修改时间猜测，容易恢复错版本。

**覆盖范围**：时间线 UI、备份版本预览、一键恢复。

---

### #63 存档世界地图生成

**功能描述**：Rust 侧解析存档的区块数据，使用图像库将每个区块的方块颜色渲染为像素，拼接生成完整的世界鸟瞰图。支持选择不同维度（主世界/下界/末地）、不同缩放级别。地图上标注玩家当前位置、已知建筑坐标、传送点。

**用户价值**：Minecraft 没有全局小地图，玩家探索了很大区域但没有整体概念。世界地图生成后，玩家可以看到「原来我的基地在北边、沙漠在东边、村庄在西南」，有助于规划下一步探索方向。地图可以导出为 PNG 图片保存。

**体验影响**：Rust 渲染——500MB 存档地图生成 < 10 秒；如果在前端 Canvas 渲染——需要 60 秒+ 且期间界面无响应。

**覆盖范围**：区块数据解析（Rust fastnbt）、像素颜色映射、多维度支持、多级缩放、标注叠加层。

---

### #64 存档统计面板

**功能描述**：深度解析存档的统计数据——矿物采集排行榜（钻石、铁、金各采了多少）、建筑方块使用排行（用了多少石头、橡木板）、生物击杀榜（杀了多少僵尸、骷髅）、探索距离（总共移动了多少格）、交通工具使用次数（坐了多少次矿车、骑了多少次马）。

**用户价值**：玩家玩了几个月的存档，不知道「我到底挖了多少钻石」。统计面板用可视化图表展示——「你在这个世界共挖掘了 3,421 块石头、发现了 47 颗钻石、击杀了 892 只僵尸、行走了 127 公里」。让玩家对自己的游戏历程有量化的认知。

**体验影响**：30+ 统计维度——玩家对自己的存档有了数据层面的理解；无统计——只有主观感受。

**覆盖范围**：stats 目录解析、区块数据补充统计、可视化仪表盘。

---

### #65 存档格式转换与迁移

**功能描述**：支持 Java 版和基岩版存档之间的格式转换（集成第三方转换工具）；支持旧版本存档逐级升级到新版本（如 1.16.5 → 1.17 → 1.18 → 1.20.1），每级升级后做校验，确保不损坏。

**用户价值**：从基岩版转到 Java 版的玩家，想把玩了很久的存档带过来。存档格式转换让这个成为可能。老玩家想把 1.12.2 的存档升级到 1.20.1，但又怕损坏——分级升级 + 逐级校验让风险可控。

**体验影响**：格式转换 + 分级升级——跨版本迁移成功率 > 85%（提前告知风险）；无工具——玩家冒险手动升级，容易损坏存档。

**覆盖范围**：外部转换工具集成、分级升级流水线、每级备份校验。

---

### #66 种子预览器

**功能描述**：输入世界种子后，即时渲染出生点附近地形的近似鸟瞰图——展示生物群系分布、村庄坐标、末地传送门位置等可预测的结构。不是精确的地形预览，但能让玩家对「这个世界大概长什么样」有基本概念。

**用户价值**：玩家创建新世界时输入了一串种子，完全不知道会生成什么。种子预览器 5 秒后展示「这是一个靠近沙漠的平原，东南 500 格处有一座村庄，东北 800 格处有黑森林」。玩家据此决定用这个种子还是换一个。

**体验影响**：Rust 生物群系映射 + 图像渲染——预览生成 < 5 秒；如果前端 JS 计算——30 秒+ 甚至不可行。

**覆盖范围**：种子→生物群系映射算法、结构定位预测、Rust image crate 渲染、多维度支持。

---

### #67 存档云端同步

**功能描述**：存档以区块级别的差异增量同步到云端（不是上传整个存档）。在多台电脑间自动保持最新状态——在家玩了存档，到笔记本上打开启动器，存档自动同步到最新。同步过程中产生冲突时（两台电脑都修改了同一区块），提供可视化冲突解决界面。

**用户价值**：在家和笔记本上玩同一个存档，不再需要手动 U 盘拷贝或者上传网盘。打开笔记本上的启动器，存档已经是家里玩到的最新进度。

**体验影响**：自动同步——存档在多设备间无缝流转；手动拷贝——每次都要手动搬运几百 MB 的存档文件夹。

**覆盖范围**：区块级 diff 检测、增量上传/下载、冲突检测 GUI、免费层 1GB / 付费层 10-50GB。

### #68 存档瘦身工具

**功能描述**：在世界地图上可视化标注区块的访问热度（玩家经过多少次、停留多长时间）。用户在地图上选择保留区域（基地、农场、常去探索区域），将未探索或极少访问的偏远区块裁剪掉。瘦身后的存档体积大幅缩减，且保留区域数据无损。

**用户价值**：玩了一年的生存存档膨胀到 5GB，但其中 80% 的区域是玩家从未去过的自动生成的区块。瘦身工具让玩家保留核心区域，裁剪无用区块，存档体积缩减 40-60%。

**体验影响**：地图选择 + 区块裁剪——直观操作 + 显著瘦身效果；无工具——存档越玩越大，不知道如何清理。

**覆盖范围**：区块热度计算、地图标注（叠加世界地图）、选择性裁剪、存档备份（裁剪前自动备份）。

### #69 存档日记

**功能描述**：自动为存档生成每日日记——今日进度摘要（新建了哪些建筑、探索了哪些新区域、击败了什么 Boss、收集了什么稀有材料），配当天游玩结束时自动截图的世界地图缩略图。日记不是长篇文字，而是数据驱动的摘要卡片。

**用户价值**：玩家玩了半年的存档，回顾时只记得「建了个大房子」和「打败了末影龙」。存档日记逐日记录了——「Day 47：开始建造自动农场，收集了 12 组铁锭；Day 89：首次进入末地，击败末影龙；Day 120：完成主基地的扩建。」这是玩家的 Minecraft 回忆录。

**体验影响**：自动生成日记——每天都有记录，形成完整的游戏叙事；手动截图记录——大部分玩家不会做，回顾时只有模糊记忆。

**覆盖范围**：每日状态快照、diff 分析、自然语言摘要生成（模板化）、世界截图附注。

### #70 存档蓝图分享

**功能描述**：在存档世界地图上框选任意区域，导出为结构文件（`.nbt`），生成该结构的 3D 预览图。用户可以分享蓝图到社区蓝图库，其他用户浏览蓝图库并导入到自己的存档中。蓝图附带标签（「中世纪」「现代化」「城堡」「红石机器」）。

**用户价值**：玩家建了一个精美的中式庭院，想分享给好友——不需要传整个存档（几百 MB），只需要导出这个庭院的结构文件（几十 KB）。好友导入后在自己的世界里放置这个庭院。

**体验影响**：蓝图导出/导入——几十 KB，导入成功率 > 95%；整存档分享——几百 MB，导入复杂。

**覆盖范围**：区域选择工具、结构导出（.nbt）、3D 预览渲染、社区蓝图库、蓝图搜索。

## 模块八、服务器管理与多人联机

> 这 10 个方向解决的是「和朋友一起玩」的全场景覆盖——从局域网到远程虚拟组网，从服务器发现到自建服务器管理。

### #71 本地服务器一键创建

**功能描述**：选择版本 → 启动器自动下载对应服务端核心 → 可视化配置（难度、游戏模式、种子、端口、最大玩家数、是否开启正版验证）→ 点击启动。服务端启动后，启动器自动将本机客户端连接到 `localhost`。服务端进程的状态（在线玩家数、TPS、内存使用）在启动器中实时展示。

**用户价值**：想和朋友在同一个局域网玩，不需要去 Minecraft 官网下载 server.jar、不需要手动编辑 server.properties、不需要记住命令行启动参数。3 分钟内从零到服务器运行。

**体验影响**：可视化创建——3 分钟内服务器运行，客户端自动连接；手动创建——下载 jar、编辑配置、命令行启动、手动连接，新手很难完成。

**覆盖范围**：服务端核心自动下载、server.properties 可视化编辑器、eula 自动同意、进程管理、客户端自动连接。

---

### #72 LAN 世界发现与直连

**功能描述**：自动扫描局域网中的 Minecraft LAN 世界（通过 UDP 多播监听），以列表形式展示——世界名称、玩家数、游戏模式。点击任意 LAN 世界一键加入，无需手动输入 IP 和端口。

**用户价值**：室友在局域网开了 Minecraft 世界，用户不需要问「你的 IP 是多少」——打开启动器的 LAN 发现面板，室友的世界已经在列表里了，点击加入即可。

**体验影响**：自动发现——LAN 世界中 3 秒内出现在列表、一键加入；手动输入——需要知道 IP:Port，很多人不会。

**覆盖范围**：UDP 多播监听、LAN 世界解析、自动连接。

---

### #73 好友联机（虚拟局域网）

**功能描述**：不在同一网络的好友可以通过启动器的虚拟局域网功能联机。技术路径分两个阶段——第一阶段使用中继服务器模式（可靠但延迟略高），第二阶段实现 P2P 直连（低延迟但受网络环境限制）。用户创建一个联机房间，获得房间码，好友输入房间码加入，所有人如同在同一局域网中。

**用户价值**：放假回家后，和学校的朋友不在同一网络，无法 LAN 联机。通过 Bonjour 建立虚拟局域网，像在学校宿舍一样联机。不需要租服务器、不需要学内网穿透。

**体验影响**：创建房间→分享码→好友加入→联机。操作时间 < 2 分钟。

**覆盖范围**：中继服务器（第一阶段）、UDP 打洞 P2P（第二阶段）、房间管理、NAT 类型检测。

---

### #74 ~ #80 其他服务器方向

**功能描述摘要**：
- **服务器收藏与管理**：每个服务器卡片实时显示在线玩家数、版本、Ping 延迟、MOTD 预览，支持分组管理。
- **服务器性能监控**：通过 RCON 获取 TPS、内存、实体数等数据，可视化仪表盘，异常时推送通知。
- **资源包自动同步**：启动器接管服务器资源包下载，后台静默完成，自动加载无需玩家确认。
- **一键模组同步到服务器**：将本地实例的模组集合同步到自建服务器，自动过滤仅客户端模组。
- **跨服传送门**：配合 Mod 实现在游戏内快速切换到收藏的其他服务器。
- **社区服务器推荐**：建立服务器发现市场，社区评分 + 标签筛选（生存、RPG、小游戏）。
- **服务器状态推送**：收藏的服务器状态变更时推送系统通知。

## 模块九、资源与内容生态

> 这 8 个方向覆盖模组之外的资源类型——资源包、光影、数据包、结构文件。这些都是 Minecraft 内容生态的重要组成部分，但在大多数启动器中被严重忽视。

### #81 ~ #88

**功能描述摘要**：
- **资源包管理**：可视化预览包内材质、拖拽排序、一键启用/禁用。
- **光影包一站式体验**：内置光影市场、效果预览图、性能评级、配置预设（低/中/高/极致）。

- **全局资源索引**：全文索引本地所有资源（模组、资源包、光影、存档、结构），跨实例引用。

## 模块十、体验与视觉

> 这 12 个方向是 Bonjour 的灵魂。竞争对手和我们的最大感知差距不在功能数量，而在「看和用的感觉」。

### #89 动态主题引擎

**功能描述**：基于 CSS 变量的完整主题系统——亮色/暗色/自动跟随系统切换；用户自定义配色方案（主色、强调色、背景色、字体大小）；社区主题市场上传和下载。主题切换实时预览，无需重启启动器。

**用户价值**：PCL2 只有几个固定主题色。Bonjour 支持用户完全自定义自己的启动器配色——深色模式 + 紫色强调色、浅色模式 + 绿色强调色。社区可以创作和分享主题。

**体验影响**：CSS 变量驱动——主题切换瞬间生效，覆盖所有页面；固定主题方案——只能选预设的几个。

**覆盖范围**：CSS 变量主题引擎、Tailwind 扩展、主题编辑器、社区主题市场。

---

### #90 动态背景系统

**功能描述**：启动器背景根据当前选中的 Minecraft 版本自动切换——1.20.1 展示樱花树林的背景，1.16.5 展示下界更新的背景。背景支持视差效果（鼠标移动时背景微微移动）和渐变过渡（切换版本时平滑过渡到新背景）。支持视频背景。

**用户价值**：选择不同版本时，背景随之变化，增强了「每个版本都是一个世界」的沉浸感。不是静态壁纸，而是有层次的动态画面。

**体验影响**：版本关联动态背景——每次切换版本都有新鲜感；静态背景——没多久就审美疲劳。

**覆盖范围**：版本→背景映射数据库、视差效果、渐变过渡、视频背景支持。

---

### #91 沉浸式版本画廊（Cover Flow）

**功能描述**：版本列表不再是一个扁平的文字列表，而是横向 Cover Flow 风格的卡片画廊。每个版本/整合包以精美卡片展示——封面图、版本号、模组数量、最近游玩时间。流畅左右滑动切换，选中的卡片放大居中，未选中的卡片缩小到两侧。

**用户价值**：浏览版本变成了视觉享受而不是查列表。滑动切换的流畅感和卡片的美感让用户觉得「这个启动器的品质不一样」。

**体验影响**：Cover Flow 画廊——版本浏览是体验的一部分；扁平列表——版本浏览是枯燥的操作。切换体验 > 4.5/5 用户评分。

**覆盖范围**：CSS 3D Transform / Framer Motion 动画、横向滑动、选中聚焦、卡片设计。

---

### #92 启动动画设计系统

**功能描述**：点击启动按钮后，启动器窗口执行一个品牌化过渡动画——启动器窗口平滑缩小并移动到屏幕角落，同时游戏窗口获得焦点并最大化。整个过程是编排好的动画序列，不是生硬的窗口切换。提供多种动画风格可选（默认、简约、像素风、电影感）。

**用户价值**：启动游戏从「启动器消失、游戏出现」的生硬切换变成「启动器优雅地把焦点交给游戏」的仪式感过渡。用户感到的是品质和用心。

**体验影响**：编排动画——启动变成有仪式感的过渡；生硬切换——启动像程序切换。

**覆盖范围**：窗口动画编排、跨进程视觉连续性、多风格可选、动画跳过选项。

---

### #93 系统级全局快捷键

**功能描述**：在任何应用中按下全局快捷键触发操作——`Cmd/Ctrl+Shift+B` 显示/隐藏启动器窗口、`Cmd/Ctrl+Shift+L` 启动默认版本、`Cmd/Ctrl+Shift+S` 截图。快捷键完全自定义，冲突时有提示。注意：Wayland 下全局快捷键需要特殊权限。

**用户价值**：不想切回启动器窗口再切换版本——全局快捷键一键启动默认版本。写代码时突然想玩一会儿，按快捷键游戏就启动了。

**体验影响**：全局快捷键——1 次按键完成操作；切回启动器窗口——3-4 次操作。

**覆盖范围**：Rust global-hotkey crate、快捷键自定义、冲突检测。

---

### #94 触控板/触摸屏手势

**功能描述**：触控板双指滑动切换版本画廊、捏合缩放到版本详情、三指打开快捷面板。触摸屏长按版本卡片弹出菜单。手势操作有动画反馈。

**用户价值**：MacBook 触控板和 Windows 平板用户可以用手势流畅操作，不需要精确点击。双指滑动浏览版本画廊的体验接近 iOS 相册。

**体验影响**：手势支持——触控/平板用户体验流畅自然；仅鼠标点击——这些设备上操作繁琐。

**覆盖范围**：wheel/touch/pointer 事件处理、手势识别映射、动画反馈。

---

### #95 音效反馈系统

**功能描述**：轻量音效设计——点击启动按钮的音效（类似 Minecraft 原版菜单点击音）、页面切换的轻柔过渡音、启动成功的提示音、错误弹出的警示音。所有音效可在设置中关闭或调节音量。

**用户价值**：交互有了声音反馈后，操作确认感更强。启动成功的提示音让用户不用盯着屏幕等——听到声音就知道游戏加载完了。

**体验影响**：音效反馈——多感官的确认感和仪式感；无声——所有操作只有视觉反馈。

**覆盖范围**：Web Audio API 播放、音效素材库、音量控制、静音选项。

---

### #96 多显示器优化

**功能描述**：启动器记住上次在哪台显示器、什么位置、什么尺寸。支持预设窗口布局——「主屏全屏」「副屏固定位置」「屏幕 2 居中」。在显示器之间切换时平滑移动窗口。

**用户价值**：有双显示器的用户——主显示器打游戏，副显示器放启动器监控服务器状态。每次打开启动器不会弹到错误的位置。

**体验影响**：位置记忆——每次打开在正确的位置；无记忆——每次打开在主屏中间，多屏用户手动拖到副屏。

**覆盖范围**：显示器 DPI 适配、窗口位置记忆、多布局预设、显示器切换检测。

### #97 多语言与本地化

**功能描述**：i18next 国际化框架 + 社区协作翻译平台。首发中文、英文、日文、繁体中文，逐步扩展到 10+ 语言。语言自动检测（基于系统语言）或手动切换。Rust 侧返回的错误消息也基于前端语言设置进行本地化输出。

**用户价值**：国际用户使用自己母语的界面。日本的 Minecraft 玩家打开启动器，所有文字都是日文。切换语言无需重启。

**体验影响**：母语界面——用户理解和操作无障碍；仅英文/中文——大量潜在用户被语言门槛挡在外面。

**覆盖范围**：i18next 框架、Crowdin 协作翻译、语言自动检测、Rust 侧本地化错误消息。

### #98 无障碍增强

**功能描述**：遵循 WCAG 2.1 AA 标准，支持屏幕阅读器友好（ARIA 标签）、高对比度主题、键盘完全可操作（Tab 键导航、Enter 键确认、Esc 键关闭）、字体大小三档调节。

**用户价值**：视障用户可以通过屏幕阅读器使用启动器；运动障碍用户可以完全通过键盘操作而不使用鼠标。

**体验影响**：无障碍——让残障玩家也能使用启动器；无无障碍——排除了这部分用户群体（而这恰恰是竞品从未关注的领域）。

**覆盖范围**：ARIA 标签、高对比度主题、键盘导航、字体调节。

### #99 数据看板

**功能描述**：展示用户个人使用数据——本周游戏总时长、最常玩的版本 Top 5、模组使用排行（安装了哪些启动时间最长的模组）、存档空间占用趋势图、启动器自身的资源使用（「本启动器仅占用 45MB 内存」）。

**用户价值**：用户了解自己的游戏习惯——「我这周玩了 18 小时，主要是 1.20.1 的科技整合包」「这个月启动 Minecraft 47 次」。数据完全本地，不上传服务器。

**体验影响**：个人数据看板——用户对自己的游戏行为有了量化认知，也是社交分享的素材。

**覆盖范围**：本地数据聚合、可视化图表、隐私保护（不上传）、启动器自身性能展示。

### #100 小部件/Tray 面板

**功能描述**：系统托盘右键菜单展示最近版本（带图标 + 上次游玩时间）+ 快速启动。此外，点击托盘图标可以弹出迷你状态面板——一个小尺寸浮动窗口，展示当前运行的 Minecraft 实例状态、网络延迟、在线时长。不需要打开主窗口。

**用户价值**：游戏运行中想快速看一下玩了多久——点托盘弹出迷你面板，不用切换窗口。

**体验影响**：托盘 + 迷你面板——核心操作 1 次点击完成；打开主窗口——窗口切换、找到信息、关闭，4-5 次操作。

**覆盖范围**：托盘菜单、迷你面板窗口（WebviewWindowBuilder）、游戏状态实时更新。

## 模块十一、AI 智能辅助

> 这 8 个方向是 Bonjour 在 2026 年的杀手级差异化——当前没有任何竞品在 AI 方面做出可用的产品。Tauri 的 Rust 后端让本地推理成为可能，不过度依赖云端 API。

### #101 崩溃智能诊断助手

**功能描述**：游戏崩溃后，用户点击「AI 诊断」按钮。系统将崩溃日志的特征发送到诊断引擎——优先使用本地 ONNX 模型（加载在 Rust 侧，延迟 < 1 秒），如果本地模型覆盖不足则调用云端大模型（延迟 < 3 秒）。诊断结果用中文给出——「你的 OptiFine 和 Sodium 冲突了，建议二选一。推荐保留 Sodium，因为其性能优化效果更好。」

**用户价值**：不用去论坛发帖「帮我看看这个崩溃是怎么回事」，不用等别人回复。点击 AI 诊断，3 秒内获得准确率 > 85% 的诊断结果和可操作的修复建议。

**体验影响**：AI 诊断——3 秒获得诊断和修复方案；论坛求助——平均等待 2 小时，回复不一定准确。

**覆盖范围**：日志特征提取、ONNX 本地推理（阶段一）、云端 LLM 推理（阶段二）、诊断结果结构化输出、中英文支持。

---

### #102 智能整合包生成器

**功能描述**：用户用自然语言描述想要的体验——「一个以科技模组为主的轻量整合包，包含自动化和物流，不要魔法模组，目标是 50 个模组以内」。AI 分析需求 → 在模组知识图谱中匹配 → 生成 20-50 个兼容模组列表 → 自动打包为整合包。用户可以预览列表并手动增删。

**用户价值**：想玩「科技+探险」但找不到现成的整合包——AI 生成一套 30 个模组的组合，初始启动成功率 > 70%。不满意可以调整需求重新生成。

**体验影响**：AI 生成——5 分钟获得定制整合包；手动搭配——30 分钟搜索+评估兼容性。

**覆盖范围**：云端 LLM API、本地模组知识图谱（Rust petgraph）、自然语言解析、兼容性验证、自动打包。

---

### #103 游戏助手（上下文搜索）

**功能描述**：启动器内置助手面板。用户在游戏中遇到问题（通过配套 Mod 在游戏内弹出助手面板），用自然语言提问——「怎么合成附魔台？」「哭泣的黑曜石哪里找？」「末地传送门怎么摆？」。助手通过本地向量搜索（Rust usearch crate，Minecraft Wiki 数据本地向量化）找到答案，图文回复。

**用户价值**：合成表记不住，不再切出去查 Wiki。在游戏内直接提问，2 秒获得答案。查找速度比翻 Wiki 快 3 倍。

**体验影响**：游戏内置助手——提问→回答 2 秒，不切屏；传统查 Wiki——切到浏览器→搜索→阅读→切回游戏，20-30 秒。

**覆盖范围**：Minecraft Wiki 数据向量化、Rust usearch 本地搜索、配套 Mod 游戏内面板、图文回复。

---

### #104 模组本地化翻译助手

**功能描述**：AI 批量翻译模组的语言文件（`.lang` / `.json`）。翻译完成后在人工校对编辑器中展示，用户可以修正翻译。修正后的翻译可以署名贡献到社区。效率比纯人工翻译高 5 倍。

**用户价值**：用户喜欢一个英文模组但苦于没有中文翻译。翻译助手自动生成初版翻译，用户花几分钟校对即可获得完整的中文模组体验。

**体验影响**：AI+人工校对——翻译一个模组 10-20 分钟；纯人工翻译——2-3 小时，很多模组因此无人翻译。

**覆盖范围**：语言文件解析、AI 批量翻译、校对编辑器、社区贡献系统。

### #105 性能调优顾问

**功能描述**：采集硬件信息 + 当前游戏设置（渲染距离、粒子效果、光影等级）→ AI 分析性能瓶颈 → 给出针对性建议——「你的 GPU 利用率仅 60%，渲染距离可以从 12 调到 18 而不会明显掉帧」「你的内存分配 2GB 偏小，建议调到 4GB」。

**用户价值**：不知道自己的电脑最佳设置是什么——要么设置保守浪费性能，要么设置激进导致卡顿。调优顾问给出基于真实硬件数据的建议。

**体验影响**：AI 调优——硬件性能最大化利用；手动试错——需要大量调整和测试。

**覆盖范围**：sysinfo 硬件采集、F3 调试数据采集、瓶颈分析算法、LLM 建议生成。

### #106 存档叙事生成

**功能描述**：基于存档的统计数据（矿物采集、生物击杀、探索距离）和关键事件（首次进入下界、击败末影龙），AI 生成冒险故事叙事——「在 Minecraft 的第 47 天，你击败了末影龙。在这段旅程中，你走过了 127 公里、挖掘了 3,421 块石头、击败了 892 只怪物。你最常用的工具是一把耐久 III 的钻石镐...」

**用户价值**：存档不只是数据和方块，它是一段冒险故事。叙事生成让玩家以故事的形式回顾自己的游戏历程，增加了情感价值和社交分享价值。

**体验影响**：AI 叙事——存档变成可阅读、可分享的故事；纯数据——存档只是冷冰冰的数据文件。

**覆盖范围**：时序事件提取、叙事模板、LLM 故事生成。

### #107 建筑灵感生成器

**用户价值**：想在 Minecraft 里建一个房子但没有灵感——灵感生成器给出参考图和方块搭配建议，用户据此开始建造。

**体验影响**：AI 灵感——5 秒获得视觉参考+方块建议；自己摸索——YouTube/Pinterest 搜索灵感，10-20 分钟。

**覆盖范围**：风格提示词、图像生成 API（可选）、方块调色板映射。

### #108 代码片段助手

**功能描述**：面向模组开发者的轻量代码检索——自然语言描述需求（如「Forge 1.20.1 如何注册一个方块」），助手匹配合适的 API 方法和示例代码片段。知识库来自 Forge/Fabric 文档的结构化索引。

**用户价值**：模组开发者不用频繁在 IDE 和文档页面之间切换。在启动器中直接问「Fabric 如何添加合成配方」，获得代码片段参考。

**体验影响**：语义搜索——自然语言得到代码参考；传统文档搜索——关键词搜索 + 阅读英文文档。

**覆盖范围**：Forge/Fabric API 文档向量化、语义代码搜索、代码片段展示。

## 模块十二、开放平台与扩展

> 这 7 个方向是 Tauri 迁移后变化最大的模块。V2.0 设想的 Node.js 插件系统、Express Web API、Node CLI 全部不可行，需要完全重新设计为 Rust/WASM 方案。

### #109 插件系统（L1 前端 + L3 WASM 插件）

**功能描述**：提供三个层级的插件能力——L1 前端插件（纯 TypeScript，注册自定义页面或组件，最安全但能力受限）、L3 WASM 插件（编译为 `.wasm`，在 Rust wasmtime 沙箱中运行，能力中等但安全且跨平台）、L2 Rust 动态库插件（高级开发者，通过 libloading 动态加载，需要数字签名验证）。插件通过 manifest 文件定义自己的权限、图标、入口。插件市场上架需经过人工安全审核。

**用户价值**：社区开发者可以扩展 Bonjour 的功能——比如一个「模组中文名索引」插件增强搜索体验、一个「服务器状态桌面小组件」插件。不需要等官方团队开发。

**体验影响**：有插件生态——用户按需扩展启动器功能；无插件——所有功能依赖官方迭代。

**覆盖范围**：L1 前端插件 SDK（TypeScript）、L3 WASM 运行时（wasmtime+WASI）、L2 动态库加载（libloading+签名验证）、插件 manifest 规范、插件市场审核。

---

### #110 主题创作工具

**功能描述**：可视化主题编辑器——颜色变量实时预览面板（修改主色调后整个启动器实时变色）、CSS 编辑器（进阶模式，支持语法高亮）、一键发布到主题市场。普通用户用调色板就能创建主题，无需写 CSS。

**用户价值**：用户不需要懂 CSS 就能创作自己的主题——选几个颜色，预览效果满意，一键发布。

**体验影响**：调色板+实时预览——5 分钟创作主题；手写 CSS——只有少数开发者能做到。

**覆盖范围**：CSS 变量控制面板、实时预览、CSS 编辑器、一键发布、主题版本管理。

---

### #111 CLI 工具箱

**功能描述**：用 Rust 编写独立的 CLI binary（`bonjour-cli`），与主程序共享核心库。支持命令——`bonjour list-instances`（列出所有实例）、`bonjour launch <instance>`（启动指定实例）、`bonjour install-mod <instance> <mod-url>`（安装模组）、`bonjour status`（查看启动器状态）。输出支持 JSON 格式（`--json`）便于脚本解析。

**用户价值**：开发者可以写脚本自动化 Minecraft 环境搭建——「在 CI 中自动创建测试实例、安装测试模组、启动游戏跑测试」。高级用户可以创建快捷启动脚本。

**体验影响**：CLI——自动化一切；纯 GUI——只能手动操作。

**覆盖范围**：Cargo workspace 共享核心库、clap 参数解析、launch / install / list / status 命令、JSON 输出模式。

---

### #112 Web API 本地服务

**功能描述**：启动器内置轻量 HTTP 服务器（Rust axum），在本地随机端口上提供 REST API——`GET /api/instances`（实例列表）、`GET /api/servers`（服务器列表）、`GET /api/game-status`（当前运行的游戏状态）。API Key 认证保护。用于第三方工具集成（如 Stream Deck 插件、桌面小组件）。

**用户价值**：第三方开发者可以编写工具读取启动器数据——桌面小组件显示「当前 Minecraft 运行了 47 分钟」、Stream Deck 上显示服务器在线状态。

**体验影响**：Web API——第三方生态可以围绕启动器生长；无 API——启动器是数据孤岛。

**覆盖范围**：axum HTTP 服务器、REST API 设计、API Key 管理、Token 权限控制。

---

### #113 Stream Deck / 宏键盘集成

**功能描述**：直接集成 Elgato Stream Deck / Loupedeck 等宏键盘设备——一键启动游戏、切换实例、查看服务器状态。在 Stream Deck 的 LCD 按键上显示 Minecraft 实例图标和状态。

**用户价值**：拥有 Stream Deck 的用户可以在物理按键上一键启动不同的 Minecraft 实例——按键 1 启动生存档、按键 2 启动测试服、按键 3 打开服务器状态。

**体验影响**：物理按键——启动游戏像按一个按键一样简单；桌面操作——需要鼠标点击 3-4 次。

**覆盖范围**：Stream Deck SDK 集成、自定义按键图标、状态同步。

---

### #114 开发者 SDK 与文档

**功能描述**：为插件开发者提供——TypeScript SDK（前端插件开发库，含类型定义和示例）、Rust SDK（WASM 插件开发的 crate，含 API 文档）、在线 API 文档站（TypeDoc + rustdoc 自动生成）、示例项目仓库（包含 L1 和 L3 插件的完整示例）。

**用户价值**：开发者不需要研究启动器的内部实现就能开发插件——SDK 提供清晰的 API 接口和完整的示例代码。

**体验影响**：有 SDK+文档——插件开发入门 < 1 小时；无 SDK——需要逆向工程，入门 > 1 天。

**覆盖范围**：TypeScript SDK（TypeDoc 生成）、Rust SDK crate（rustdoc 生成）、在线文档站、示例仓库。

---

### #115 社区翻译平台集成

**功能描述**：将 Bonjour 的 i18n 翻译文件接入 Crowdin 或 GitLocalize 等社区翻译平台。CI/CD 自动拉取社区贡献的翻译 → 检查覆盖率 → 合并到主分支。前端展示各语言的翻译进度（如「日文 87%、韩文 42%」）。

**用户价值**：全球社区玩家可以贡献自己语言的翻译，加速 Bonjour 的国际化进程。翻译贡献者在 About 页面被署名致谢。

**体验影响**：社区翻译 + CI 自动化——新语言支持速度快；纯官方翻译——人力有限，覆盖面窄。

**覆盖范围**：Crowdin/GitLocalize 集成、CI/CD 自动拉取翻译、翻译覆盖率仪表盘、贡献者署名。

## 模块十三、安全与隐私

> 这 5 个方向利用 Tauri 的 Rust 后端实现竞品无法企及的安全能力——字节码级别的模组安全扫描、系统级凭据存储、AES-256 加密备份。

### #116 模组安全扫描

**功能描述**：扫描每个模组 `.jar` 文件的字节码——检测危险 API 调用（`Runtime.exec()` 可能执行恶意命令、`File.delete()` 可能删除用户文件、`Socket.connect()` 可能连接外部服务器窃取数据）。扫描结果标注风险等级——安全（无危险调用）、可疑（包含网络通信或文件操作但无法判断意图）、危险（包含明显的恶意行为模式）。危险模组自动隔离并弹出警告。

**用户价值**：Minecraft 模组社区多次出现伪装成热门模组的恶意 jar 包——它们窃取用户账号、删除文件、植入挖矿程序。安全扫描在用户安装前发出警告，拦截已知恶意模式检出率 > 98%。

**体验影响**：安全扫描——安装前就知道模组是否安全，危险模组自动拦截；无扫描——用户从不可信来源下载模组时完全不知道风险。

**覆盖范围**：字节码扫描（Rust 解析 Java class file）、危险 API 模式匹配、三级风险标注、社区举报 + 人工审核。

---

### #117 隐私仪表盘

**功能描述**：透明展示 Bonjour 收集和使用的所有数据——什么数据（如崩溃报告、使用统计、性能数据）、数据存储在哪里（本地 / 加密上传）、是否必须上传（可选 / 匿名 / 必须）。每项数据收集都有开关控制，所有遥测均需用户明确同意（Opt-in），默认关闭。

**用户价值**：用户对「这个启动器会不会收集我的隐私」不再有疑虑——隐私仪表盘透明展示一切，用户可以完全控制。GDPR 合规让欧洲用户也能放心使用。

**体验影响**：透明可控——用户信任；黑盒收集——即使不收集也会被怀疑收集。

**覆盖范围**：数据用途声明、每项数据开关、GDPR 合规设计、首次启动隐私确认。

---

### #118 家长控制

**功能描述**：家长面板（密码保护）——设置每日游戏时长上限（到时间游戏自动保存退出）、限制可访问的服务器（白名单制）、禁止服务器多人聊天、生成游戏报告（本周玩了多久、登录了哪些服务器）。

**用户价值**：家长可以放心让孩子玩 Minecraft——不用担心沉迷（有时长上限）、不用担心和孩子一起玩的人不安全（服务器白名单）、不用盯着孩子玩（有游戏报告）。

**体验影响**：家长控制——家长安心、孩子在一定范围内自由游玩；无控制——家长不放心，可能完全不让孩子玩。

**覆盖范围**：使用时间追踪 + 上限、服务器白名单、聊天限制开关、游戏报告、密码保护设置。

---

### #119 文件完整性校验

**功能描述**：所有下载的文件（版本核心、模组、资源包、光影包）在下载完成后自动进行 SHA-256 校验，与官方或社区数据库中的已知哈希值比对。如果校验失败（文件下载不完整或被篡改），自动重新下载，不将损坏文件写入实例目录。

**用户价值**：用户永远不需要担心「这个下载的模组是不是完整」——校验完全自动化，损坏的文件不会进入游戏环境。减少了「模组装好了但启动报错，最后发现是 jar 下载不完整」的痛苦诊断。

**体验影响**：自动校验——下载失败自动重试，用户无感知；无校验——下载不完整导致启动失败，用户需要自己排查是哪个文件坏了。

**覆盖范围**：下载完成事件 → SHA-256 计算 → 数据库比对 → 失败自动重试。

---

### #120 数据备份保险箱

**功能描述**：对启动器关键数据（配置文件、账号信息、实例定义）进行 AES-256 加密备份。备份可以存储在——本地加密文件、用户指定的云端位置、外部硬盘。增量备份（只备份自上次以来的变化），定期自动校验备份完整性。

**用户价值**：用户电脑重装系统后，不需要重新配置启动器——恢复加密备份，所有实例、模组列表、配置一键还原。

**体验影响**：加密备份——数据安全且可恢复；无备份——系统重装 = 所有配置丢失。

**覆盖范围**：AES-256 加密（Rust aes-gcm）、增量备份、多目的地（本地/云端/外置）、定期校验。

## 模块十四、Tauri 迁移创造的新方向

> 这 16 个方向是 V2.0 完全没有的——它们是 Tauri 迁移后才浮现的独特机会。每个方向都利用了 Tauri 的某个独特优势（Rust 性能、系统级能力、WASM 沙箱、WebSocket 通信等）。

### #121 启动器性能基准与竞品对比仪表盘

**功能描述**：在 CI 中自动下载并测量 Bonjour 与 PCL2、HMCL、PrismLauncher 的性能数据——安装包大小、冷启动时间（从点击到窗口出现）、热启动时间、内存占用（空闲时）、CPU 占用（空闲时）。生成一个性能对比页面，内置在启动器的 About 页面中，用户可以随时查看数据。

**用户价值**：这不是一个功能，而是一项营销资产。「Bonjour 冷启动 0.8 秒，PCL2 需要 6.3 秒」——这种量化对比是说服竞品用户迁移的最强力证据。不需要说「我们更快」，直接展示数据。

**体验影响**：可视化性能对比——用数据说话；口头宣传——没有说服力。

**覆盖范围**：CI 自动化竞品性能测试、对比图表生成、About 页面内嵌展示。

---

### #122 沙箱化的模组测试环境

**功能描述**：利用 Rust 在不同操作系统上创建隔离的文件系统 overlay——在隔离环境中安装和测试新模组，不影响现有实例。测试完成后，用户可以选择——「合并到主实例」（确认安全兼容）、「丢弃」（不满意或有问题）、「保留」（继续测试）。

**用户价值**：想试一个新模组但不确定会不会搞坏现有配置——沙箱测试让用户在隔离环境中先试试，安全了再合并。不怕「装了之后启动崩溃」。

**体验影响**：沙箱测试——试模组零风险；直接安装——装坏了要花时间恢复。

**覆盖范围**：overlay 文件系统（Linux overlayfs / macOS clonefile / Windows hardlink）、测试环境管理、合并/丢弃/保留三种结果。

---

### #123 游戏内 Mod：启动器-游戏实时通信桥

**功能描述**：编写一个轻量 Fabric/Forge Mod，通过本地 WebSocket 连接到启动器的 Rust 后端。实现双向通信——启动器可以推送事件到游戏内（如「好友上线了」「模组有更新」），游戏内可以请求启动器操作（如「帮我切换一下光影包」「打开 AI 助手面板」）。

**用户价值**：这是 Bonjour 从「外部工具」变成「游戏内伙伴」的关键功能——玩家在游戏中不需要切出来就能切换资源包、查看启动器通知、向 AI 助手提问。所有竞品都只是外部启动器，没有一个做到游戏内深度集成。

**体验影响**：游戏内深度集成——启动器成为游戏体验的一部分；外部启动器——游戏内仍然需要切出来操作。

**覆盖范围**：Rust tokio-tungstenite WebSocket 服务、配套 Mod（Fabric/Forge）、JSON 协议双向通信、游戏内悬浮 UI。

---

### #124 Rust 原生 NBT 编辑器

**功能描述**：使用 Rust NBT 解析库实现内嵌 NBT 编辑器——支持解析 level.dat、player data、区块数据。以 JSON 树的形式可视化展示 NBT 数据结构，支持编辑、保存和校验。比社区常用的 NBTExplorer（C# 实现）快 10 倍。

**用户价值**：玩家可以通过 NBT 编辑器修改存档数据——修改游戏模式、更改物品属性、修复损坏的 NBT 数据。不需要下载第三方 NBT 编辑器，在启动器中一站式完成。

**体验影响**：Rust 解析——500MB 存档秒级打开；传统工具——大存档等待 10-20 秒。

**覆盖范围**：fastnbt 解析、JSON 树编辑器（前端）、保存校验、level.dat / player data 专项支持。

---

### #125 崩溃知识图谱社区

**功能描述**：每个崩溃报告经 AI 诊断后，将（模组列表 + 错误特征 + 解决方案）匿名上传到社区知识图谱。图谱使用 Rust petgraph 构建——节点是「模组 X」「错误类型 Y」「解决方案 Z」，边是「模组 X + 模组 Y → 错误类型 Z → 解决方案 W」。新用户崩溃时，在知识图谱中秒级匹配已有案例。

**用户价值**：社区知识图谱随着用户使用不断增长——从最初的 100+ 条手动规则迅速扩展到 10,000+ 个节点。新崩溃案例匹配成功率不断提升，「罕见错误」也逐渐被覆盖。

**体验影响**：知识图谱——崩溃解决方案的匹配成功率不断提升、延迟 < 1 秒。

**覆盖范围**：崩溃特征提取、匿名上传、petgraph 知识图谱构建、秒级匹配。

### #127 跨平台原生通知中心

**功能描述**：使用 Rust notify-rust crate 发送系统原生通知——Windows Toast 通知、macOS Notification Center 通知、Linux D-Bus 通知。支持通知分类（游戏崩溃、模组更新、服务器状态变更、好友上线），用户可以按分类开关通知。提供通知历史面板。

**用户价值**：游戏在后台运行时崩溃了，用户在做别的事情——系统通知栏立即弹出「Minecraft 崩溃，点击查看诊断」。模组更新后，通知推送「3 个模组有新版本」，用户不用手动检查。

**体验影响**：系统原生通知——到达率 > 99%，即使用户不在启动器界面也能收到；HTML5 通知——可能被浏览器/系统限制，到达率低。

**覆盖范围**：notify-rust 集成、分类通知开关、通知历史面板、通知分组。

### #128 Rust 端多线程并行下载引擎

**功能描述**：利用 Rust 多线程实现分片并行下载——单文件被切分为 8 个分片，通过 HTTP Range 请求并行下载，最后合并。效果上类似 IDM（Internet Download Manager）的下载加速。配合自动选择最优下载源，实现最大带宽利用。

**用户价值**：下载 Minecraft 版本核心（200MB+）时，传统单线程下载速度可能只有 3-5MB/s；并行下载可以将速度推至 20-30MB/s（取决于带宽和服务器限制）。1GB 大小的版本下载速度比竞品快 2 倍。

**体验影响**：8 线程并行——大文件下载速度显著提升；单线程——下载速度受限于单连接。

**覆盖范围**：HTTP Range 分片、tokio::task::JoinSet 并发、分片合并校验、下载进度聚合。

### #129 低端机器 Lite 模式

**功能描述**：Rust sysinfo 检测硬件配置——CPU 核心数 < 2 或内存 < 4GB 时标记为低端机器。前端自动切换到 Lite 模式——禁用 Cover Flow 动画（改为纯文本列表）、取消动态背景（改为单色背景）、禁用粒子动画、降低 UI 刷新率。Lite 模式内存占用 < 80MB，FPS 保持 > 30。

**用户价值**：拥有老旧电脑（4GB RAM、双核处理器）的 Minecraft 玩家不需要担心启动器本身拖慢电脑——Lite 模式让启动器在低端机器上也流畅运行。这部分用户恰恰是竞品体验最差的群体（PCL2 和 HMCL 在低端机器上也很慢）。

**体验影响**：Lite 模式——低端机器流畅运行，享受核心功能；完整模式——低端机器卡顿，可能放弃。

**覆盖范围**：硬件配置自动检测、UI 降级策略、内存优化（禁用预加载、减少缓存）。

### #130 WASM 模组兼容性模拟器

**功能描述**：利用 Rust 嵌入的 WASM 运行时（wasmtime），编写一个简化的 Minecraft 类加载器模拟器（编译为 WASM）。在用户选择一组模组后，模拟器在 WASM 沙箱中虚拟加载所有模组的类，检测类加载冲突——类重复定义、类版本不一致、MixIn 目标冲突。这个过程完全不需要启动真实 Java 进程，5 秒内完成 50 个模组的虚拟冲突检测。

**用户价值**：用户在装模组前就能知道潜在的类加载冲突，不需要装完→启动→崩溃→排查。虚拟检测 < 5 秒，检出率 > 60%（后续迭代提升）。

**体验影响**：WASM 虚拟检测——快速、安全、不需要 Java 进程；Java Agent 检测——需要启动真实 JVM，慢且有安全风险。

**覆盖范围**：wasmtime 运行时、ClassLoader WASM 模拟实现、批量虚拟加载、冲突报告生成。

### #131 嵌入式市场/内容分发平台

**功能描述**：Rust axum 在启动器内部运行轻量 Web 服务器，前端通过 iframe 或专用页面展示自建的中文模组/资源市场。市场内容来自爬虫 + 人工审核——收录中文模组、中文资源包、中文整合包。不依赖 CurseForge/Modrinth 的 UI，提供中文优先的浏览体验——中文模组名、中文描述、中文评价。

**用户价值**：中国玩家不再需要在 CurseForge 的英文界面中艰难浏览——中文市场展示的中文模组都有中文名称和描述，模组评价也是中文玩家的真实反馈。

**体验影响**：中文优先市场——中国玩家浏览和发现内容的效率提升 3-5 倍；英文市场——语言门槛高，很多优秀模组被埋没。

**覆盖范围**：爬虫 + 人工审核内容索引、Rust axum API、前端中文市场页面。

### #132 JSON 配置的 GUI Schema 编辑器

**功能描述**：很多模组的配置文件是 JSON 格式——Rust serde 自动推断 JSON Schema → 前端根据 Schema 动态生成表单 GUI（文本输入框、下拉选择、滑块、布尔开关）→ 用户在 GUI 中编辑配置，无需打开 JSON 文件手动修改。保存时 Rust 校验 JSON 格式正确性。

**用户价值**：用户想改「Dynmap」的网页端口配置——不需要找到插件文件夹、打开 JSON 文件、看懂 JSON 结构、手动编辑、担心格式错误。GUI Schema 编辑器自动生成表单，用户填写数字、选择选项，不用担心 JSON 语法。

**体验影响**：GUI 表单——编辑配置像填表单一样直观，无出错风险；手动编辑 JSON——需要理解 JSON，容易写错格式。

**覆盖范围**：JSON Schema 推断（Rust serde）、前端动态表单生成、保存格式校验。

### #133 系统级游戏录屏（Rust + FFmpeg）

**功能描述**：Rust 调用系统 FFmpeg（需要用户预先安装或附带 portable 版本），录制 Minecraft 游戏窗口的视频——支持录制最后 30 秒（Instant Replay，类似 Nvidia ShadowPlay）或手动开始/停止录制。录制的视频保存为 MP4，可一键分享。

**用户价值**：玩家在游戏中完成了精彩操作，想保存下来——点击「保存最近 30 秒」，不需要提前开始录制。CPU 额外开销 < 10%（利用硬件编码），1080p 30 秒视频 < 15MB。

**体验影响**：Instant Replay——不预录也能保存精彩时刻；传统录屏——需要提前开始录制或事后全程回放。

**覆盖范围**：Rust Command 调用 FFmpeg、Instant Replay 循环缓冲、手动录制、硬件编码加速。

### #134 游戏启动参数 A/B 测试工具

**功能描述**：玩家想比较不同的启动配置——Java 8 vs Java 21、分配 4GB vs 8GB 内存、使用 G1GC vs ZGC。A/B 测试工具自动运行两组配置——每组启动 3 次取平均值——记录启动时间、游戏内 FPS（通过 Mod 上报）、内存使用。最后生成对比报告，用图表展示差异。

**用户价值**：社区里关于「Java 8 还是 Java 21 玩 MC 更好」「多少内存合适」的争论永无止境。A/B 测试工具让用户在自己的硬件上用数据说话——「在你电脑上，Java 21 启动快 12%、FPS 高 5%」。

**体验影响**：A/B 测试——用数据做决策；靠感觉和看论坛——决策没有针对自己的硬件优化。

**覆盖范围**：Rust 循环启动管理、启动时间/内存/Mod FPS 数据采集、统计对比图表。

### #135 离线包管理器

**功能描述**：在联网电脑上「预取」一切所需——模组、版本核心、Java 运行时、资源包、光影，全部下载后进行 SHA-256 校验，打包为 `bonjour-offline.zip`。移植到完全离线的电脑上，导入离线包，启动器自动完成全部安装配置，用户可以在离线电脑上正常游玩。

**用户价值**：学校的机房电脑断网、公司的办公电脑无法访问外网——在这些电脑上也可以玩 Minecraft。只需要在家的联网电脑上「预取」一次，导出离线包，U 盘带到离线电脑上导入即可。

**体验影响**：离线包——断网也能玩完整 Minecraft（单机）；依赖在线下载——断网 = 无法安装新版本和新模组。

**覆盖范围**：全量资源预取 + 校验、zip 打包（Rust）、离线导入安装流程。

### #136 实例依赖健康检查

**功能描述**：Rust 扫描每个实例中安装的模组——检查每个模组是否有已知 CVE（Common Vulnerabilities and Exposures）安全漏洞、检查模组是否已停止维护（最近一次更新超过 1 年）、检测是否有更好的替代模组（功能相同但更新更活跃的模组）。生成「实例健康报告」——标注安全风险、推荐替代模组。

**用户价值**：用户的一个实例中有个 2 年没更新的模组——这个模组可能有安全漏洞，且没人修复。健康检查告诉用户：「模组 X 已停止维护 2 年，存在 CVE-2023-XXXX 漏洞（高危）。社区推荐替代模组 Y，功能相同且活跃维护。」用户一键替换。

**体验影响**：安全健康报告——长期维护的实例保持安全健康；无检查——过期模组积累安全风险，用户不知道。

**覆盖范围**：CVE 数据库本地缓存、模组维护状态爬取、替代模组推荐算法。
